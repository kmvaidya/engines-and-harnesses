## Short version

- **The family tree has collapsed.** Of the five projects in the brief, two
  are dead as products. Roo Code shut down its extension, Cloud and Router on
  May 15, 2026 and archived the repo [P]. Continue was acquired by Cursor in
  June 2026; its repo is read-only after a final 2.0.0 release [P]. Kilo Code
  was acquired by Anaconda (announced about July 17, 2026) and keeps shipping
  [P banner, S date]. Cline and Zed are the two independent survivors.
- **Both survivors rebuilt their harness in 2026 for the same stated reason:
  the 2024 harness was written for weaker models.** Cline's founder calls the
  old XML-tool harness "a period piece" built "around Claude 3.5 Sonnet" and
  reports about 10x fewer stuck tasks on the new one (6.34% to 0.62% of tasks
  hitting the mistake limit); the extension is "installed by over 11 million
  developers" [P]. Kilo threw away its Roo-derived core and
  rebuilt the VS Code extension on the MIT-licensed OpenCode server [P].
- **Extensions are becoming one surface among several on a shared runtime.**
  Cline now ships the same `@cline/sdk` runtime in VS Code, JetBrains, a CLI,
  a desktop app and Kanban [P]. Kilo runs the same OpenCode-based engine in
  VS Code, JetBrains, CLI, cloud agents and a desktop app [P].
- **Edit formats converged on "per-model tool".** Cline routes GPT/Codex
  models to `apply_patch` and everyone else to an `editor` tool; a session never
  gets both [P]. Kilo exposes `edit`, `write` and `apply_patch` ("used with
  certain models") [P]. Zed has `edit_file` (targeted replace) and `write_file`
  [P]. Roo's SEARCH/REPLACE `apply_diff` with fuzzy matching is now history.
- **Indexing split stays real.** Cline still refuses embeddings and reads files
  on demand; its enterprise page repeats that it ~~"does not index or embed
  repository contents"~~ [R: not verbatim] "doesn't index or embed the
  contents of your repositories" [P]. Kilo kept Roo's opt-in embeddings index (LanceDB
  default, Qdrant optional; off by default) [P]. Zed's agent uses grep,
  find_path and diagnostics, no index [P].
- **OS sandboxing reached the OSS editors in 2026.** Zed turned on Seatbelt
  (macOS) and Bubblewrap (Linux) sandboxing by default in release 1.14 for its
  agent's `terminal` and `fetch` tools (Aug 5, 2026) [P]. Kilo has the same two
  backends but off by default, and no Windows support [P]. Cline's docs describe
  approvals only, no sandbox [P].
- **ACP is the interop story.** Zed created the Agent Client Protocol (Aug
  2025), JetBrains co-develops it (Oct 2025), and the official list now names
  49 agents and 21 editor clients, including GitHub Copilot, Cursor, Cline,
  Claude Agent and Codex CLI [P]. VS Code support exists only through
  third-party extensions [P].
- **Philosophies differ on where the human sits.** Cline: approve every edit
  and command by default [P]. Roo's CEO: "If an agent can make a good pull
  request with a single prompt, the way you interact changes completely" [S].
  Kilo: "The IDE is not over" [P]. Zed: "LLMs automate typing, not thinking"
  [P] and threads should replace PRs (Delta, Sep 2026) [P].
- **For the bank [O]:** Cline's Feb 2026 npm compromise came from an AI issue
  triage bot with shell access reading attacker-written issue titles [P]. It is
  the cleanest real-world example of prompt injection reaching a release
  pipeline in a coding-agent vendor.

### 1.2 Agent loop

- **Plan and Act.** "Plan mode lets you explore and strategize without
  changing files." In Plan mode Cline "can read your codebase, run searches,
  and discuss strategy, but cannot modify any files or execute commands." You
  switch to Act manually; history carries over. An optional setting uses a
  different model per mode. Tagline: "Think first, then build." [P for the
  two Plan-mode quotes; P* for the tagline]
  https://docs.cline.bot/core-workflows/plan-and-act.md
- **Single loop, now stateless.** The May 2026 SDK post describes a stateless,
  reusable low-level loop wrapped by a stateful runtime that handles
  durability, so "long-running work" survives a UI restart and sessions move
  between surfaces [P] (Renee Huang, May 13, 2026).
- **Subagents.** `spawn_agent`; several can run in parallel; each returns its
  final reply to the main agent, which waits. Subagents get no MCP tools.
  Available in CLI and Desktop, not in the VS Code or JetBrains extensions.
  Safety detail: "Approving the `spawn_agent` call approves everything the
  subagent then does." [P*] https://docs.cline.bot/features/subagents.md
- **Agent teams** (CLI, SDK, Kanban only). A coordinator delegates to
  specialist agents, with shared task board, mailbox and mission log,
  persisted in `~/.cline/data/db/teams.db`; start with `/team`. Not available
  with `--yolo`. [P] https://docs.cline.bot/cli/agent-teams.md
- **Done / stuck signals.** Built-in tools include `ask_question` and
  `submit_and_exit` [P]. The harness tracks `task.mistake_limit_reached`,
  which fires after three consecutive mistakes and stops to ask the user [P]
  (migration post).
- **Kanban.** A board where each card is a live agent task; tasks can depend
  on each other and auto-start. "Cline Kanban is agent agnostic," supporting
  Claude Code and Codex as well as Cline [P*] (Sidd Sant, Mar 26, 2026).

### 1.3 Tools and edit format

Current built-in tools (ClineCore, SDK runtime) [P]
https://docs.cline.bot/exploring-clines-tools/cline-tools-guide:

`read_files`, `search_codebase`, `run_commands`, `fetch_web_content`,
`apply_patch`, `editor`, `skills`, `ask_question`, `submit_and_exit`, plus
`spawn_agent` in CLI/Desktop.

- **Edit format is routed by model.** "Act mode offers `apply_patch` to GPT
  and Codex models and to every model on the OpenAI (`openai-native`)
  provider"; other models get `editor`; Plan mode offers neither; a session
  offers "`editor` or `apply_patch`, never both." SDK callers override with
  `toolRoutingRules`. [P]
- **Legacy names** (`read_file`, `replace_in_file`, `execute_command`,
  `use_skill`) belong to the old XML-tag harness. Older blog posts and third-party
  guides that describe `replace_in_file` SEARCH/REPLACE blocks,
  `list_code_definition_names` or `browser_action` describe the pre-2026
  harness [P]. The docs page does not say what operations `editor` supports
  [P, gap].
- **Native tool calling.** The old harness described tools in the system
  prompt and parsed XML tags from the model's text output. "Models in 2026 are
  RL-trained to call tools natively." [P] Native tool calling first shipped
  in v3.35, Oct 31, 2025 [P] (archive title).

### 1.4 Context

- **No indexing, by design** (possibly stale: May 27, 2025). Nick Baumann:
  "We don't index your codebase, and this choice isn't an oversight." "Every
  merge is a potential divergence between reality and your AI's
  understanding." "Your codebase isn't just text – it's your competitive
  advantage." Cline "reads it, sees an import, follows it." [P]
  https://cline.bot/blog/why-cline-doesnt-index-your-codebase-and-why-thats-a-good-thing
  The stance is current: the Enterprise overview says Cline reads files only
  when a task needs them and ~~"does not index or embed repository contents"~~
  [R: paraphrase shown as quote] "doesn't index or embed the contents of your
  repositories" [P].
- **Critique on record [S]:** Hacker News commenters argued that following
  imports with grep is still retrieval, just not vector retrieval. Do not
  present "no RAG" as "no retrieval" [O].
- **Rules.** Workspace rules in `.clinerules/` or `.cline/rules/`; global
  rules in `~/Documents/Cline/Rules` (also `~/.cline/rules`). Also reads
  `.cursorrules`, `.windsurfrules`, `AGENTS.md` at project root and
  `~/.agents/AGENTS.md`. CLAUDE.md is not mentioned. Each rule has a toggle.
  Conditional rules use a `paths:` glob array in YAML frontmatter; invalid
  YAML fails open (rule activates). [P] https://docs.cline.bot/customization/cline-rules.md
- **Memory Bank is a methodology, not a feature.** Copy instructions into a
  rule file; the agent maintains six markdown files in `memory-bank/`
  (`projectbrief.md`, `productContext.md`, `activeContext.md`,
  `systemPatterns.md`, `techContext.md`, `progress.md`) [P]
  https://docs.cline.bot/best-practices/memory-bank.md
- **Compaction.** Auto Compact summarizes near the context limit; falls back to
  rule-based truncation on unsupported models; works alongside Focus Chain, a
  todo list re-injected periodically [P/S]. The doc lists Claude 4, Gemini 2.5,
  GPT-5, Grok 4 as supported models, so it predates the SDK rebuild (possibly
  stale). The SDK posts only say context management was "tightened" [P].

### 1.5 Safety

- **Default: ask.** "Every file edit and terminal command requires your
  approval, so you stay in control of what actually changes." [P] README.
- **Auto-approve** per category: read project files, read all files, edit
  project files, edit all files, safe commands, all commands, browser, MCP
  (plus a notifications toggle). Docs: "Leave edits, commands, browser, and
  MCP off until you have a specific reason". [P]
- **Command risk is classified by the model, not a list.** "Cline does not
  use a fixed allowlist." The model sets `requires_approval` per command. [P]
  https://docs.cline.bot/features/auto-approve.md [O: for a bank this is the
  weak point; the classifier is the model being guarded.]
- **YOLO mode** auto-approves everything; "YOLO mode disables all safety
  checks." [P] ~~Enterprise admins can control it.~~ [unverified: no
  mention of admin control of YOLO on the auto-approve page, the Enterprise
  overview or the pricing page, 2026-11-04]
- **No sandbox** is described in the docs; guidance is "isolated environments"
  and "throwaway projects" for YOLO [P]. Checkpoints (shadow snapshots) give
  undo [P].
- **Enterprise.** BYO inference (Bedrock, Vertex, Azure OpenAI, Anthropic,
  OpenAI, any OpenAI-compatible endpoint), "No markup, no vendor lock-in", SSO,
  Member/Admin/Owner RBAC, per-team model and tool controls, remote config,
  OpenTelemetry export, telemetry that "doesn't include your code, file
  contents or prompts" except via Cline's own providers [P*]
  https://docs.cline.bot/enterprise-solutions/overview.md
- **Incident, Feb 17, 2026.** An attacker published `cline@2.3.0` to npm with
  a `postinstall` that installed `openclaw` globally; live about 8 hours. Root
  cause: a GitHub Actions workflow (added Dec 2025) used an AI agent with shell
  access to triage issues, so a crafted issue title could run code; it shared a
  cache scope with the release workflow, which exposed publish secrets.
  Reported Jan 1, not fixed until public disclosure Feb 9; then "the wrong
  token was deleted while the exposed one remained active." Fix: AI triage
  removed, OIDC provenance publishing, no long-lived tokens. VS Code and
  JetBrains builds unaffected. [P] https://cline.bot/blog/post-mortem-unauthorized-cline-cli-npm
  (Verification detail: the workflow was added Dec 21, 2025 and used
  `claude-code-action` with the Bash tool, triggerable by any GitHub user; the
  report came from researcher Adnan Khan; fixed release 2.4.0 at 11:23 AM PT.
  [P*])

### 1.6 Extensibility

- **MCP** with a marketplace; enterprise MCP server controls [P].
- **Skills** (v3.48, Jan 10, 2026) [P].
- **Hooks and plugins (SDK).** A plugin object has `name`, `manifest`
  (capabilities), `setup(api, ctx)` and `hooks`. Seven hook points:
  `beforeRun`, `afterRun`, `beforeTool`, `afterTool`, `beforeModel`,
  `afterModel`, `onEvent`. `beforeTool` can return `{ skip: true, reason }` to
  block a call. "Hooks are code logic (callbacks) that fire at fixed points
  inside the agent loop." [P*] (Etisha Garg, Jun 15, 2026). File-based hooks
  first shipped in v3.36 (Nov 6, 2025) [P].
- **SDK.** Layered TypeScript packages; provider layer `@cline/llms` usable
  alone; custom providers via an `ApiHandler`. "The runtime is open because
  the use cases should not be limited to the surfaces we ship ourselves." [P]
- **Headless/CI** mode in the CLI [P]. **ACP:** `cline --acp`, used by Zed,
  JetBrains AI Chat, Neovim (CodeCompanion, avante.nvim), Emacs agent-shell;
  "Nothing is auto-approved by default" [P*] https://docs.cline.bot/usage/acp.md

### 1.7 Model coupling

Model-agnostic. 300+ models through the Cline provider, 50+ BYO-key
providers, local models; can import a conversation from Claude Code or Codex
and continue it on a cheaper open-weight model [P] (Desktop post). Cline does
not train its own model [O: none announced]. Since mid-2026 it leans hard into
open-weight models: ClinePass, open-sourced evals for open-weight agents (Aug
18, 2026), NVIDIA Nemotron partnership posts (Aug to Oct 2026) [P archive].
The migration post reports Kimi K3 at 82.02% on Terminal-Bench 2.0 in Cline's
harness, the top figure in Cline's own comparison table against Hermes and
OpenCode [P, vendor self-reported].

### 2.2 Architecture as last shipped (historical; possibly stale, frozen May 2026)

- **Fork of Cline.** Kilo's post credits Roo with popularizing "custom modes,
  the Architect/Code/Debug split, and diff-based editing" [P; the page
  writes it as "Custom modes, the Architect/Code/Debug split, diff-based
  editing", without "and"]
  https://blog.kilo.ai/p/thank-you-roo.
- **Modes.** Built-ins Code, Architect, Ask, Debug, Orchestrator, plus custom
  modes [P]. A mode = `slug`, `name`, `roleDefinition` ("placed at the
  beginning of the system prompt"), optional `whenToUse` (guides automatic
  mode switching), `customInstructions` ("added near the end of the system
  prompt"), and `groups` of tools (`read`, `edit`, `command`, `mcp`). The
  `edit` group can be restricted by `fileRegex` on relative paths. Project
  modes in `.roomodes`; global in `custom_modes.yaml`. Each mode remembers its
  own model ("sticky models"). [P*]
- **Orchestrator / Boomerang.** Orchestrator calls `new_task` with a
  `message` and a `mode`; the parent pauses. "Each subtask operates in complete
  isolation with its own conversation history." The child ends with
  `attempt_completion`; "The parent task resumes with only the summary."
  Orchestrator by default cannot read or write files, call MCP or run
  commands, to keep its context on coordination. Subtask creation and
  completion each need approval by default. [P*]
  https://roocodeinc.github.io/Roo-Code/features/boomerang-tasks
- **Edit format.** `apply_diff`: multiple SEARCH/REPLACE blocks, each with a
  `:start_line:` hint; fuzzy match by Levenshtein distance on normalized text,
  searching 40 lines around the hint, threshold "typically 0.8-1.0". Later
  versions also listed `edit`, `edit_file`, `apply_patch`, `search_replace`.
  [P*]
- **Indexing (opposite of Cline).** Optional semantic index: Tree-sitter
  chunks (100-1,000 chars), embeddings from OpenAI, Gemini, Ollama, Mistral,
  Bedrock and others, stored in Qdrant; exposed as a `codebase_search` tool.
  [P*] https://roocodeinc.github.io/Roo-Code/features/codebase-indexing

### 2.3 Philosophy

- Matt Rubens (co-founder, CEO): "If an agent can make a good pull request
  with a single prompt, the way you interact changes completely." [S] Digital
  Today, Apr 24, 2026, citing The New Stack.

### 3.4 Context and memory

- **Rules:** AGENTS.md, custom rules, custom instructions [P docs index].
  The old Roo-style memory bank under `.kilo/rules/memory-bank/` is

- **Built-in memory (new):** off by default, per project. Stored outside the

  correct | forget`; saving asks approval each time. A compact index is

### 3.5 Safety

## 6. Agent Client Protocol (ACP)

- **What:** "an open standard that enables any agent to integrate seamlessly
  with any editing environment." Modeled on LSP. Local agents run as editor
  subprocesses speaking JSON-RPC over stdio; remote agents over HTTP or
  WebSocket ("Full support for remote agents is a work in progress"). Reuses
  MCP JSON types where possible and adds types such as diff display. [P*]
  https://agentclientprotocol.com/, https://zed.dev/acp
- **Who:** "Created by Zed, grown by a community of editors and agents." First
  integration was Google's Gemini CLI (Aug 27, 2025). JetBrains agreed to
  co-develop it and ship it across its IDEs (Oct 6, 2025). [P*]
  Repo: Apache-2.0, 4.6k stars, SDKs in Kotlin, Java, Python, Rust, TypeScript
  [P] https://github.com/agentclientprotocol/agent-client-protocol.
- **ACP Registry** (Jan 28, 2026): register an agent once, install it in any
  client; built into Zed and JetBrains; "implement once, work everywhere" [P*]
  https://zed.dev/blog/acp-registry.
- **Adapters:** Zed wrote `codex-acp` and the Claude adapter, then said it
  would shift "to working with the community on the future of the protocol"
  [P*] (Oct 16, 2025, possibly stale).
