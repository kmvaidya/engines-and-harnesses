# Open-source terminal coding agents (round 5, 2026-11-04)

**Tag legend.** [P] confirmed on the primary source (vendor or author page, repo, release notes, registry) fetched on 2026-11-04. ## Short version

- [P] **OpenCode is the adoption leader by a wide margin**: 224,627 GitHub stars (MIT), ahead of OpenAI's Codex CLI (133,222) and the Claude Code repo (154,566, which carries no open-source licence). Its homepage claims 16M monthly developers [P, vendor claim, unaudited]. It shipped a ground-up **OpenCode 2** on 2026-09-11 (npm `@opencode/cli` 2.0.0): one background server per user that the TUI, desktop and web clients all attach to.
- [P] **OpenCode 2 dropped two v1 selling points**: it no longer runs LSP servers ("V2 accepts and preserves `lsp` configuration, but it does not run language servers, expose LSP tools, or produce LSP diagnostics.") and it "currently only discovers `AGENTS.md`", not `CLAUDE.md`. The guide frames the CLAUDE.md gap as a compatibility issue to report, so it may not be permanent. Its base system prompt is about 111 words; the Anthropic-specific add-on is 49 words, after the "legacy Anthropic prompt" was removed on 2026-09-05 (PR #47447) and comment-density guidance was appended on 2026-09-11 (PR #48444).
- [P] **Pi reversed its most quoted rule.** Mario Zechner wrote in Nov 2025 "pi does not and will not support MCP". Pi 0.99.0 (2026-09-29) and 1.0 (2026-10-01) ship MCP, "codemode" (model-written JavaScript in a QuickJS sandbox that calls tools) and tool search as built-in extensions. Default tools are still only `read`, `bash`, `edit`, `write`; there are still no built-in sub-agents or plan mode. Pi now lives at Earendil (acquired 2026-04-08), has 120,102 stars, and powers OpenClaw (393,923 stars).
- [P] **Goose left Block.** Block donated it to the Linux Foundation's Agentic AI Foundation (AAIF announced 2025-12-09; repo moved to `aaif-goose/goose` on 2026-04-07). Goose 2.0 (beta since 2026-04-08) makes ACP its single client protocol, rewrites desktop in Tauri, and on 2026-09-16 replaced "the classic agent loop with a re-entrant state machine". Its experimental macOS seatbelt sandbox was removed.
- [P] **Aider has gone quiet.** Last release v0.86.2 on 2026-02-12, last merge 2026-05-22, polyglot leaderboard last updated 2025-11-20. Its ideas (tree-sitter repo map, edit-format benchmarking, architect/editor split, a git commit per change) are still the best-documented research in this space, but it is no longer an active project. A community fork (cecli, ex aider-ce) carries on.
- [P] **Crush (Charm)** is Go, licensed FSL-1.1-MIT (source-available, converts to MIT later), 28,960 stars, the only one here with first-class LSP tools (`lsp_references`, `lsp_rename`, etc.), and v0.99.0 (2026-10-29) shipped 13 hook events that "Most hook scripts written for Claude Code run under Crush unchanged."
- [P] **Kimi CLI (Python) is archived**; Moonshot replaced it with Kimi Code CLI (TypeScript, MIT, 8,130 stars, v2.5.0 on 2026-11-04). **Qwen Code** (Apache-2.0, 29,015 stars) forked Gemini CLI v0.8.2, stopped syncing, and now markets "feature parity with Claude Code".
- [P] **Nobody in this group sandboxes by default.** OpenCode: "`shell` runs with the host user's filesystem, process, and network authority." Pi: "does not include a built-in permission system". Goose removed its seatbelt sandbox. Only Qwen Code (inherited from Gemini CLI) lists a sandbox. Bank readers should treat every one of these as "runs as you".
- [O] The feature sets have converged: string-replace edit tools, AGENTS.md, Agent Skills (`SKILL.md`), MCP, Claude-Code-compatible hooks, and a client/server split (OpenCode 2, Goose 2 via ACP, Crush `serve`, Qwen `serve`) now appear across nearly all of them. What still differs is philosophy, governance and safety defaults.

## 2. Aider (Paul Gauthier)

### What it is
- [P] "AI Pair Programming in Your Terminal" (README). Python, Apache-2.0, repo created 2023-05-09. README badges claim 6.8M PyPI installs and 15B tokens/week [P, vendor badge].
- [P] Release history: v0.82.0 2025-04-14, v0.83.0 2025-05-09, v0.84.0 2025-05-30, v0.85.0 2025-06-27, v0.86.0 2025-08-09 (GitHub releases); v0.86.1 2025-08-13 and v0.86.2 2026-02-12 on PyPI only. Last commits: GPT-5.5 settings by Gauthier on 2026-04-24/25; last merged PR 2026-05-22.
- [P] The README still says "Aider works best with Claude 3.7 Sonnet, DeepSeek R1 & Chat V3, OpenAI o1, o3-mini & GPT-4o", which shows how long the front page has gone without an update.
- [P] Polyglot leaderboard "last updated" 2025-11-20; top is gpt-5 (high) at 88.0% with `diff` format. Possibly stale.
- [P] Community fork: PyPI `aider-ce` describes cecli as "a community-driven fork"; newer pages say it was renamed `cecli-dev`. Its 0.97.0 page lists planned sub-agents, hooks and "hashline-based file editing" [P, plans only].

### Loop and modes
- [P] Single chat loop with chat modes; architect mode splits each task across two models (2024-09-26): "An Architect model is asked to describe how to solve the coding problem. An Editor model is given the Architect's solution and asked to produce specific code editing instructions to apply those changes to existing source files." Motivation: o1-class models "are strong at reasoning, but often fail to output properly formatted code editing instructions." Best result then: 85.0% (o1-preview architect with o1-mini or DeepSeek editor). Possibly stale (2024).
- [P] README: "Automatically lint and test your code every time aider makes changes" and fix what linters and tests report. That is its verification step.

### Edit formats
- [P] https://aider.chat/docs/more/edit-formats.html lists `whole` (return the full file), `diff` (search/replace blocks shaped like git merge-conflict markers), `diff-fenced` (path inside the fence, "primarily used with the Gemini family of models"), `udiff` (simplified unified diff, used for GPT-4 Turbo to cut laziness), and `editor-diff` / `editor-whole` for architect mode.
- [P] Laziness study, Paul Gauthier, 2023-12-21: unified diffs took GPT-4 Turbo from 20% to 61% on an 89-task refactoring benchmark, with lazy comments on 12 tasks dropping to 4. Opening line: unified diffs "significantly reduces its bad habit of "lazy" coding, where it writes code with comments like "…add logic here…"." Possibly stale (2023 models).
- [P] His four edit-format principles (same post), verbatim:
  - "FAMILIAR - Choose an edit format that GPT is already familiar with."
  - "SIMPLE - Choose a simple format that avoids escaping, syntactic overhead and brittle specifiers like line numbers or line counts."
  - "HIGH LEVEL - Encourage GPT to structure edits as new versions of substantive code blocks (functions, methods, etc), not as a series of surgical/minimal changes to individual lines of code."
  - "FLEXIBLE - Strive to be maximally flexible when interpreting GPT's edit instructions."
  - Plus: "A helpful shortcut here is to have empathy for GPT, and imagine you are the one being asked to specify code edits."

### Context: the repo map
- [P] Post dated 2023-10-22 (no byline): "aider sends GPT a concise map of your whole git repository that includes the most important classes and functions along with their types and call signatures. This repository map is now built automatically using tree-sitter to extract symbol definitions from source files." Ranking: "a graph ranking algorithm, computed on a graph where each source file is a node and edges connect files which have dependencies", fitted to "the token budget assigned by the user (via the --map-tokens switch, which defaults to 1k tokens)". It keeps "the most important identifiers, the ones which are most often referenced by other portions of the code."
- [P] Repo map work continues in small community PRs (bash tree-sitter tags merged 2026-05-16).

### Git as the safety model
- [P] https://aider.chat/docs/git.html: "Whenever aider edits a file, it commits those changes with a descriptive commit message." "Aider will first commit any preexisting changes with a descriptive commit message." "`/undo` will undo and discard the last change." Commits get "(aider)" appended to author/committer names. Opt out with `--no-auto-commits`.
- [O] Aider has no sandbox and no permission prompts for edits; the undo story is git. That is a coherent design for a pair-programming tool where the human watches every turn, and a weak one for unattended runs.

### Models
- [P] Model-agnostic via litellm; per-model settings pick the edit format (e.g. v0.85.5 made `diff` required for GPT-5). Gauthier does not train models.
- [P] Self-hosting metric: release notes print "Aider wrote 88% of the code in this release" (v0.86.0).

### Direction
- [P] No release in almost nine months and no roadmap posted. [O] Treat Aider as the historical reference for edit formats and repo maps, not as a live product choice.

## 3. OpenCode (Anomaly, formerly SST)

### What it is
- [P] "The open source AI coding agent." MIT, TypeScript, repo created 2025-04-30, now `anomalyco/opencode` (old `sst/opencode` redirects). Homepage: "With over 220,000 GitHub stars, 950 contributors, and over 20,000 commits", and 16M monthly developers [P, vendor claim].
- [P] Surfaces: "Available as a terminal interface, desktop app, and IDE extension"; v2 docs add a web app and Docker images. Logins: "Log in with GitHub to use your Copilot account" and "Log in with OpenAI to use your ChatGPT Plus or Pro account". "75+ LLM providers through Models.dev, including local models."
- [P] Pricing: "OpenCode is 100% free to use." Paid model access: the gateway formerly called Zen is now documented as **OpenCode Console**, "an AI gateway", pay-as-you-go, selling "at cost, with markup only to cover processing fees" (4.6% + $0.31 per credit purchase); **OpenCode Go** is a subscription with included usage.
- [P] Privacy line on homepage: "OpenCode does not store any of your code or context data, so that it can operate in privacy sensitive environments."

### OpenCode 2 (the big recent change)
- [P] npm `@opencode/cli` created 2026-09-02; 2.0.0 published 2026-09-11; 2.1.0 2026-10-20; 2.2.0 2026-10-27. v1 continues in parallel (v1.19.5 on 2026-10-28).
- [S] One server per user that the TUI, desktop, web and editors attach to (webreactiva.com summary of the v2 docs). Dax Raad reportedly called 2.0 a ground-up rebuild after 0.x as prototype and 1.x as validation, and the team moved from Bun to Node for memory reasons (InfoQ/Huxiu/KuCoin coverage; not checked against a primary).
- [P] Migration guide (https://opencode.ai/v2/docs/migrate-v1/), verbatim:
  - "V2 accepts and preserves `lsp` configuration, but it does not run language servers, expose LSP tools, or produce LSP diagnostics." It recommends "the project's lint, typecheck, or compiler commands" instead. (Verification pass: the earlier version of this note cut the sentence after "language servers" and added a full stop.)
  - "If a V1 setup relied on a `CLAUDE.md` fallback, move that guidance into the applicable `AGENTS.md`. V2 currently only discovers `AGENTS.md`; because non-API V1 behavior is intended to remain compatible, also file a compatibility issue with the affected project details." (Verification pass: the two sentences appear in this order on the page; the second continues past the semicolon.)
  - "V1 plugin implementations do not run in V2."
  - "V1 asks before accessing paths outside the project. V2 does not: `external_directory` is allowed by default."
- [S] A search snippet of the v2 LSP page says LSP is not implemented "yet" rather than removed for good; the page itself returned 404 when fetched.
- [P] 2.1.0 (2026-10-20) brought back `todowrite` behind an experimental setting; 2.2.0 (2026-10-27) restored it in desktop as opt-in, added desktop plugins, and removed the OpenCode GitHub Action ("no longer published").

### Loop, agents, tools
- [P] Primary agents `build` ("Default coding agent") and `plan` ("Explores and plans without editing normal project files"; denies edits except under `~/.opencode/plan`); subagents `general` ("cannot launch more subagents") and `explore`; hidden `compaction`, `title`, `summary` agents. Custom agents are markdown files in `.opencode/agents/<name>.md`; subagents run in child sessions, foreground or background, with fresh context.
- [P] Tools (v1 docs, https://opencode.ai/docs/tools/): `bash`, `edit` ("exact string replacements"), `write`, `read`, `grep`, `glob` (both on ripgrep), `apply_patch`, `skill`, `todowrite`, `webfetch`, `websearch` (Exa/Parallel or OpenCode providers only), `question`, and `lsp` (experimental flag). [O] Two edit tools side by side: str_replace for most models and an `apply_patch` tool in the Codex format.
- [P] Per-model system prompts in `packages/core/src/plugin/system-prompt/`: `anthropic.txt`, `gpt.txt`, `gpt-astra.txt`, `kimi.txt`, `meta.txt`, `trinity.txt`. Word counts measured on 2026-11-04: base `system.txt` 111, anthropic 49, gpt 396, gpt-astra 585, kimi 1,411, meta 1,250, trinity 1,257. The Anthropic file is now only comment-density guidance ("By default, match the surrounding comment density: where the code has none, add none."); commit "feat(core): update GPT prompts and remove legacy Anthropic prompt (#47447)" landed 2026-09-05, and "append comment guidance to Anthropic system prompt (#48444)" on 2026-09-11 [P, GitHub commits API].
- [O] That spread (49 words for Claude, 1,400 for Kimi) is a clean example of the round-1 thesis: newer frontier models get thinner prompts; weaker or less-tuned models still get long ones.

### Context
- [P] AGENTS.md only in v2. Compaction is a hidden agent; 2.2.0: "Start session history from the latest completed compaction." Plugins can add "keyed session instructions" that are appended at the next step "Instead of editing the system prompt and busting the prompt cache", and they "survive compaction and reverts". Configurable prompt-cache TTL per provider/model (2.2.0).

### Safety
- [P] Permissions are one ordered array; "The last matching rule wins". Base policy starts with allow-all (`{ "action": "*", "resource": "*", "effect": "allow" }`), then asks for `*.env` files. "If no rule matches, OpenCode uses `ask`." No OS sandbox: "`shell` runs with the host user's filesystem, process, and network authority."
- [O] For a bank: OpenCode's default is permissive (allow-all base, external directories allowed in v2). It needs an explicit deny/ask policy file before anyone points it at real code.

### Extensibility
- [P] MCP, skills, plugins (new v2 plugin API, TUI plugins on OpenTUI 0.7, desktop GUI plugins), SDK packages `@opencode/sdk`, `@opencode/client`, `@opencode/ai` (Promise API at root, Effect API at `/effect` from 2.2.0).

### Anthropic dispute (dated facts only)
- [S] 2026-01-09: subscription OAuth tokens stopped working in third-party tools including OpenCode (piunikaweb, falcao.org). 2026-02-19: Anthropic docs updated to say such use breaks its terms (Gigazine, AlternativeTo).
- [P] 2026-03-19: PR #18186 "anthropic legal requests" by `thdxr` (Dax Raad), merged 2026-03-19 04:45 UTC: "Remove anthropic references per legal requests", removing the Anthropic prompt file (`anthropic-20250930.txt`), provider hints, the built-in `opencode-anthropic-auth` plugin and the provider enum entry. Claude is still usable through API keys and other providers (homepage still lists Claude).

### Philosophy (from their own text)
- [P] The Nov 2025 README FAQ "How is this different than Claude Code?" (commit 8063e645, 2025-11-20; removed from the README by May 2026, so possibly stale):
  - "Not coupled to any provider. ... As models evolve the gaps between them will close and pricing will drop so being provider-agnostic is important."
  - "A focus on TUI. OpenCode is built by neovim users and the creators of terminal.shop; we are going to push the limits of what's possible in the terminal."
  - "A client/server architecture. This for example can allow OpenCode to run on your computer, while you can drive it remotely from a mobile app. Meaning that the TUI frontend is just one of the possible clients."
  - The same list had "Out of the box LSP support", which v2 dropped.
- [P\*] Dax Raad (2025 Baseten interview, quoted on the Latent Space wiki; the Baseten page did not render): "It's just the experience around it is better." Possibly stale.
- [P] Their current system prompt bans a construction the house style also bans: "Do not introduce unprompted alternatives through framing such as "X, not Y" or "This isn't about X. It's about Y."" (`gpt-astra.txt`).

### Direction (shipped)
- [P] v2 line: single server, desktop refresh, desktop plugins, image and "decision generation" APIs for plugins (experimental), session media blobs, Windows persistent terminals. No public roadmap document found.

## 4. Goose (AAIF, originally Block)

### What it is
- [P] README: "your native open source AI agent — desktop app, CLI, and API — for code, workflows, and everything in between" and "Not just for code — use it for research, writing, automation, data analysis". Rust, Apache-2.0, repo created 2024-08-23. "15+ providers", "your existing Claude, ChatGPT, or Gemini subscriptions via ACP", "70+ extensions via the Model Context Protocol".
- [P] AAIF formed 2025-12-09 with MCP (Anthropic), goose (Block) and AGENTS.md (OpenAI) as founding projects. Press release describes goose as "an open source, local-first AI agent framework". Manik Surtani, Head of Open Source at Block: "goose was our first step".
- [P] Michael Neale, 2026-04-07: "Block has donated goose to the Agentic AI Foundation (AAIF) at the Linux Foundation." Repo moved from `block/goose` to `aaif-goose/goose`; docs to goose-docs.ai.
- [P] GOVERNANCE.md core values: "Our goal is to make goose the most hackable agent available." "Flexible: we prefer open models – but we don't restrict ourselves." "Choice: We're not bound to any one model, protocol, or stack."

### Loop

## 9. Our analysis for the deck [O]

1. **Pi is the best story for "harness philosophy", and it now has a second act.** The 2025 essay is the cleanest statement of minimalism by a builder. The 2026 reversal shows how it held up: four default tools and a sub-1,000-token prompt survived, "no MCP" did not, and MCP came back in a shape that keeps it out of the context window by default (deferred exposure, called through code). Use both quotes together.
2. **OpenCode's per-model prompt files are hard evidence for the thin-prompt thesis.** 49 words for Anthropic models against 1,400 for Kimi is a slide by itself, and it is a file anyone in the room can open.
3. **Client/server is the 2026 architecture move.** OpenCode 2, Goose 2 (ACP), Crush `serve` and Qwen `serve` all split the agent core from the UI. For bank engineers, it is the same shape as Copilot's cloud agent and SDK: the "agent" is a service, the terminal is one client.
4. **Open source here does not mean safer by default.** None of the profiled agents sandboxes shell commands out of the box. Pi's docs are the most honest about it and point to micro-VMs and containers.
5. **Governance diverges more than features do.** Linux Foundation (Goose), VC-backed company with a free tool and a paid gateway (OpenCode), company with an MIT core and planned Fair Source and proprietary tiers (Pi; "PBC" status of Earendil not checked in the verification pass), source-available FSL (Crush), model vendors (Qwen, Kimi), and a one-person project gone quiet (Aider).
6. **Agent-generated PRs are changing how these projects accept contributions.** Goose closes PRs that do not implement a "Ready" issue; Pi auto-closes first-time contributors' issues and PRs; Zechner cites "the influx of agent-generated slop".
