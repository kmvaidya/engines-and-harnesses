## Short version

1. **The enterprise tier is consolidating into bigger platforms.** Tricentis bought Tabnine (Jul 30, 2026) [S, press release via BusinessWire]. Atlassian says "Rovo Dev is reaching end of life as a standalone product" and its CLI "is evolving into the unified Atlassian Rovo CLI experience" [P]. Tabnine put its own CLI "in maintenance mode" and now ships a branded OpenCode build [P]. Two enterprise vendors now ship an open-source harness instead of their own: Tabnine (OpenCode) and, in a different way, GitLab and JetBrains, whose sandboxes run Anthropic's open-source `sandbox-runtime` (SRT) [P].
2. **Air-gap is a short list.** Vendors that document a fully disconnected deployment: Tabnine ("can also be deployed in a completely air-gapped environment") [P], IBM Bob ("in customer-controlled environments, including air-gapped environments") [P], JetBrains AI Enterprise via IDE Services with on-prem OpenAI-compatible servers [P], GitLab Self-Managed with Duo Self-Hosted (vLLM) [P\*], Mistral Vibe Enterprise on-prem [P], plus every open-source harness pointed at a local model. Copilot, Claude Code, Codex, Cursor, Devin, Kiro, Antigravity and Grok Build all need a vendor or hyperscaler endpoint [O from the table in Part B].
3. **Copilot's sandbox is off by default after GA.** GitHub's docs: "Local sandboxing is turned off by default." It runs on Microsoft eXecution Container (MXC): Seatbelt on macOS, bubblewrap on Linux, and the ProcessContainer backend's "BaseContainer tier" on Windows 11 25H2 with KB5124010 or 26H1 with KB5124006 [P]. Admins can force it on and make it fail closed [P]. On Windows the network host rules rely on "programs honoring the proxy settings" [P].
4. **Windows sandboxing splits the field.** Native OS sandbox on Windows: Copilot CLI (MXC), Codex (MXC), Antigravity (AppContainer), Kiro (AppContainer, admin setup) [P/P\*]. No native Windows sandbox: Claude Code ("runs commands unsandboxed"), Cursor (not documented), Devin CLI, Junie ("not supported on Windows"), GitLab editor sandbox, Kilo, Grok Build (docs name only Landlock and Seatbelt), Qwen Code (Docker or Podman only) [P].
5. **Pricing has moved to credits almost everywhere.** Copilot replaced premium requests with AI credits on June 1, 2026; Business includes 1,900 credits per user per month, Enterprise 3,900, "1 AI credit = $0.01 USD"; completions stay unlimited [P]. Kiro, JetBrains, Antigravity, IBM Bob ("Bobcoins"), GitLab ("GitLab Credits"), Atlassian ("Rovo Credits" from Dec 3, 2026), Codex (ChatGPT credits) and Cursor (shared pools) all meter usage [P/P\*].
6. **One harness reads another vendor's policy file.** Grok Build reads a subset of Claude Code's `managed-settings.json` "for compatibility", and its own `/etc/grok/requirements.toml` wins [P]. Grok also reads `CLAUDE.md`, `.claude/rules/` and `.cursor/rules/` [P]. Qoder, Rovo Dev, Mistral Vibe, GitLab Duo and Grok Build all read AGENTS.md [P].
7. **Qoder is the one harness here whose maker trained a model inside the product.** Alibaba calls Qwen-Coder-Qoder "a large-scale reinforcement learning model" trained with "real product environments", and reports code retention up 3.85%, tool anomalies down 61.5%, tokens down 14.5% (vendor claim) [P].

# Part C. Sandbox gaps from the critic

## C1. Copilot CLI and app (local sandboxing, GA Oct 7, 2026)

All [P], GitHub docs markdown fetched Nov 4, 2026 (URLs in frontmatter).

- **Default state.** "Local sandboxing is turned off by default. Until you enable it, the shell commands that Copilot runs execute directly on your machine with the same access as your user account". The configuring page: "Local sandboxing is turned off by default unless enterprise managed settings require it."
- **Mechanism.** "Local sandboxing is powered by Microsoft eXecution Container (MXC), a cross-platform technology that provides a common interface to the isolation mechanisms available on each operating system."
  - macOS: "the Seatbelt backend", macOS 15 or later recommended.
  - Linux: "the bubblewrap backend", bwrap 0.5.0+, plus `slirp4netns`, util-linux 2.35+, iptables with `nf_tables`, `/dev/net/tun` when outbound traffic is allowed.
  - Windows: "Windows 11 version 25H2 with update KB5124010 or later, or Windows 11 version 26H1 with update KB5124006 or later, with support for the BaseContainer tier of the ProcessContainer backend." The MXC README lists `processcontainer` as the Windows default backend, `bubblewrap` for Linux, `seatbelt` for macOS, with other Windows backends `windows_sandbox`, `wslc`, `microvm`, `hyperlight`, `isolation_session` (Linux also `lxc`). Only Windows Sandbox, MicroVM and Hyperlight are starred as experimental. [R] Earlier draft listed WSLC as experimental; the README does not star it. The Windows prerequisite quote is on the using and configuring pages, not the concepts page.
- **Strength, in GitHub's words.** "Local sandboxing currently sits at the lighter-weight end of this spectrum: it restricts what a process can read, write, and reach on the network, but it does not run your commands inside a separate virtual machine or container."
- **Gap inside the CLI.** "Because the CLI itself is not sandboxed, the operating-system sandbox never sees the file operations these tools perform and cannot constrain them. Instead, the built-in tools are coded to check the sandbox policy themselves and honor your configured settings on a best-effort basis."
- **Defaults once enabled.** Writes to the working directory and temp; "Outbound internet access is on by default. Local network access is off."; Git and `gh` auth on; local MCP and LSP servers sandboxed by default; "Remote MCP servers are never sandboxed."; bypass requests "enabled by default".
- **Windows network weakness.** "On Windows, the sandbox relies on programs honoring the proxy settings. As a result, these controls do not provide the same protection against direct connections as on macOS and Linux."
- **Fail closed.** With managed `sandbox.enabled` and `sandbox.failIfUnavailable` both true, "the CLI blocks model requests and tool execution for the session if it cannot enforce sandboxing." Otherwise an unsupported host runs unsandboxed with a notice.
- **Billing.** "Local sandboxing is included in the standard GitHub Copilot seat at no additional cost."
- [R] CP §5 quoted CLI v1.0.100 "Sandbox allows local network access by default". Current docs say local network is "Turned off by default" in the CLI, while "By default, both network settings are turned on in the app." The Enterprise Cloud copy of the page still shows the older default and calls sandboxing experimental. Use the dotcom docs and say which surface.
- [O] This closes CP §11's open question ("Which OS mechanism MXC uses on each platform"): Seatbelt, bubblewrap, and Windows ProcessContainer (BaseContainer tier). Not AppContainer by name.
