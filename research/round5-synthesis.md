## 1. Short version

1. **The loop is the same everywhere.** Every harness profiled runs one model-driven tool loop that ends when the model replies without a tool call or calls a completion tool. Subagents, plan mode and `/goal` loops sit on top. A source study of Claude Code says "Most of the code, however, lives in the systems around this loop" (arXiv 2604.14228) [P, CV §5]. Factory's definition: "An agent harness is everything around the model: the prompts, the tools, how tool results come back, and the loop that runs it all" (Oct 29, 2026) [P, PL §4.9].
2. **Labs are deleting harness code; everyone else is building infrastructure around it.** Claude Code removed Glob, Grep and the todo tools for new models and re-derives its system prompt for every model [P, CC §3, §8]. Cursor cut 66% of its system prompt [P, CU A4]. Augment rebuilt Auggie on Pi with four tools: "subtraction" [P, PL §5.2]. Meanwhile Cursor, Cognition, GitHub, Amp and Factory spend on cloud VMs, routers, control planes and their own models [O, PD §1.1].
3. **Two edit formats won, and the model's maker picks.** GPT-family models get `apply_patch`; Claude, Gemini, Grok and most others get exact string replacement. Copilot, Cline, OpenCode and OpenHands route edit tools by model family [P, CV §2.2]. Fast-apply rewrite models (Cursor's 2024 design) are gone from the open harnesses read [O, CV §2.3].
4. **Grep beat embeddings, with one big exception.** Cursor measured a 12.5% gain from semantic search in Nov 2025 and turned the embeddings index off in July 2026 for a local grep index [P, CU A3]. A source study of 11 harnesses found "No system uses vector-embedding RAG for code retrieval" [P, CV §3.2]. GitHub Copilot went the other way and turned semantic search on by default in the CLI on Oct 19, 2026 [P, GH §3.1].
5. **The same harness now runs behind every surface.** Copilot ("Microsoft Copilot harness", Oct 28, 2026), Codex (one Rust core behind CLI, IDE, ChatGPT desktop and SDK), Kiro (one harness process over ACP), Antigravity (App and CLI share a harness), Cline and Kilo (shared SDK or OpenCode server) [P, GH, CX, GAJ, OI]. Terminal agents moved to client/server too (OpenCode 2, Goose 2, `crush serve`, `qwen serve`) [P, OT].
6. **Harness and model are co-designed in both directions.** OpenAI ships per-model harness settings as data in `models.json` [P, CX §7], and Andrew Ambrosino (Codex design and engineering) told Every on Oct 15, 2026: "So we do training on the harness now." [P on Every's transcript, which Every labels "not certified verbatim", PA §2.1]. Microsoft trained MAI-Code-1-Flash "directly with GitHub Copilot harnesses used in production" [P, GH §7]. Cursor trains Composer with RL inside its own harness [P, CU A7]. Google lists "Integrate the Antigravity product agent harness with the Gemini training and evaluation stacks" as a goal [P, GAJ §1.4].
7. **Safety moved from per-call prompts to classifiers plus sandboxes, and defaults still vary widely.** Claude Code made classifier-reviewed auto mode the starting mode on 2026-09-28 and published a 17% miss rate on real overeager actions [P, CC §5]. Codex, Cursor, Copilot and Antigravity also ship model reviewers [P]. OS sandboxes (Seatbelt, bubblewrap, Landlock, AppContainer, MXC) exist in most vendor tools, but are off by default in Claude Code, Kiro, Gemini CLI, Kilo, the Antigravity CLI, Grok Build and Copilot's local sandbox ("Local sandboxing is turned off by default", unless managed settings require it); none of the open-source terminal agents sandbox by default [P, CC, GAJ, OI, OT, EH §C1]. Two open components carry much of this layer: Anthropic's `sandbox-runtime` (Claude Code, Junie, GitLab Duo) and Microsoft's MXC (Copilot, Codex) [P components, O grouping, EH §C4].
8. **Open standards cover the edges, not the core.** AAIF (Linux Foundation) now holds MCP, AGENTS.md, Agent Skills, A2A and goose among 10 projects; ACP (Zed and JetBrains) is the editor-to-agent protocol; Claude Code's hook vocabulary is copied without a standard [P, CV §1]. None of them standardises the loop, prompt or context management [O, PD §3.7].
9. **Multi-agent settled on one writer and many readers.** Cognition: "multi-agent systems work best today when writes stay single-threaded" (Apr 22, 2026) [P, CU B8]. Cursor Projects' coordinator "doesn't write code itself" [P, CU A2]. Parallel writers are used only with worktrees or separate VMs [O, PD §1.4].
10. **Consolidation was heavy in 2026.** Cursor to SpaceX (closed Aug 14), Windsurf rebranded as Devin Desktop (Jun 2), Gemini CLI consumer tier cut (Jun 18) and Jules shut (read-only Nov 11), Amazon Q Developer folded into Kiro, Roo Code shut (May 15), Continue to Cursor, Kilo to Anaconda, Augment's agent stack to Harness (Oct 8), Pi to Earendil [P, CU, GAJ, OI, PL, OT].
11. **Usage shifted toward agents and away from Copilot's lead, while Gartner still names GitHub a Leader.** JetBrains' 2026 survey: Claude Code used at work by 39% (18% in January), Copilot 21%, Codex 16% [P, PD §3.1]. Stack Overflow 2026: Claude Code 65.5%, Copilot 58.7% of 12,255 respondents [P, AM §4.1]. Gartner's first Enterprise AI Coding Agents MQ (May 20, 2026) names Anthropic, Cursor, GitHub and OpenAI as Leaders [S placements, AM §1.2], and GitHub says it "placed as the highest in ability to execute" [P, vendor claim]. The share of GitHub PRs opened by agents is somewhere between 20.8% and "more than 40%" depending on who counts (Amplifying, Microsoft, Octoverse) [P, AM §2.1, §3]. METR warns self-reported speedups are "not necessarily grounded in reality" [P, PD §3.1]; DORA found the highest-budget teams got "only a marginal increase in software delivery throughput at a 10x increase in cost" [P, AM §4.3].
12. **Swapping only the harness can move scores a lot when it fixes a real limit, and little when it does not.** One harness change took an open-weight model from 43 to 72 solved SWE-bench Verified tasks with a 20k-token window and made no difference at 262k (102 vs 101) [P, HE §2]. Scale's SWE-Bench Pro V2: "the task explains 32% of the variance in solved-or-failed, the model 2.7% and the scaffold 0.3%" [P, HE §6.1]. The "45.9% vs 55.4%" Claude Code figure is an aggregator error; the measured gap from Scale's standard harness to Claude Code is 3.9 points [R, HE §1.1]. Vendor head-to-heads each show the vendor's own harness winning or tying [P, vendor claims, HE §5].
13. **Enterprise deployment is a short list at the strict end.** Of the vendors profiled, only Tabnine, IBM Bob, JetBrains AI Enterprise, GitLab Self-Managed with self-hosted models and Mistral Vibe Enterprise document an air-gapped or fully on-prem option, plus any open-source harness pointed at a local model; Copilot, Claude Code, Codex, Cursor, Devin, Kiro, Antigravity and Grok Build need a vendor or cloud endpoint [P per vendor, O list, EH §B1]. The enterprise tier is consolidating: Tricentis bought Tabnine [S], Tabnine's own CLI is "in maintenance mode" and replaced by a branded OpenCode build [P], and "Rovo Dev is reaching end of life as a standalone product" [P, EH §A1, §A3]. Pricing moved to metered credits almost everywhere, including Copilot since Jun 1, 2026 [P, EH §B2].
14. **For a Copilot-only bank** [O]: Copilot now sits in the multi-model, one-harness-every-surface, keep-an-index, governance-first corner, supports every open standard listed above, and can host Claude and Codex harnesses (and Codex inside Copilot for JetBrains). The evidence does not support "Copilot costs you 10 to 20 points" against Claude Code or Codex; the levers a team controls (context management, checking work before finishing, model and effort, network access, turning the sandbox on) show larger measured effects (HE §10). The transferable patterns are tool-neutral.

## 3. What they all share (the common core)

**3.1 One model-driven loop.**
- Claude Code SDK docs: "Claude continues calling tools and processing results until it produces a response with no tool calls." [P, CC §2]
- Copilot SDK docs: "The CLI is purely mechanical: "model asked for tools → execute → call model again." The **model** is the decision-maker for when to stop." [P, GH §2.1]
- Pi: "If tool results or queued messages require another model request, Pi starts another turn. Otherwise, the run ends." [P, OT §6]
- Explicit completion tools are the variant: Gemini CLI `complete_task`, Cline `submit_and_exit`, Copilot `task_complete` and SDK `isTerminal`, OpenHands `FinishTool`; Codex ends a turn with a message on the `final` channel [P, CV §5.1, CX §2, PL §1.2].
- Thorsten Ball (Apr 15, 2025, older than 6 months): "It's an LLM, a loop, and enough tokens." [P, PL §3.8]. Willison (Sep 18, 2025, older than 6 months): "An LLM agent runs tools in a loop to achieve a goal." [P, CV §5]
- Barbaste et al. (arXiv 2609.00006, submitted Jul 15, 2026), Observation 1: "loop sophistication does not predict benchmark performance. Mini-SWE-Agent's minimal linear loop achieves reported results in the same range as OpenHands's event-sourced conversation engine" [P, HE §8.1]. The scores compared are self-reported, and the authors say the matched comparison "is an open question that this study does not answer" [P]. (An "Observation 5" mismatch seen in arXiv's HTML is a conversion artifact; the PDF cites Observation 1 [R on the mismatch].)

**3.2 The same tool categories.** Read, search, edit, execute, web, delegate. Rombaut (13 agents): "the same four core capability categories (read, search, edit, execute) appear across all LLM-driven agents" [P, HE §8.2; upgraded from P\*]. Pi, Auggie v2 and Claude Code's newest default set are close to the minimum: read, bash, edit, write [P, OT, PL, CC].

**3.3 Layers every serious harness adds** [O, CV §5.2, confirmed against the sibling files]:
1. Instruction files (AGENTS.md read nearly everywhere; vendor files alongside) [P, CV §1.6].
2. Compaction by LLM summary (Claude Code, Codex local path, Copilot, OpenCode, OpenHands condenser, Amp since May 2026) [P].
3. Subagents with their own context returning summaries (Claude Code, Codex, Copilot, Cursor, Devin, Antigravity, Junie, Kiro, OpenCode, Cline CLI) [P].
4. A plan mode that removes write tools (Claude Code, Codex "decision complete" plans, Copilot enforced in the runtime, Cursor, Gemini CLI default-on, Antigravity `/plan`, Junie plan documents, Cline Plan/Act, OpenCode `plan`) [P].
5. Approval modes plus an optional OS sandbox [P, §4.3 below].
6. MCP, Agent Skills and hooks [P, CV §1.6].
7. A headless or SDK mode (`claude -p`, `codex exec`, Copilot SDK, `agent -p`, `droid exec`, `kilo run --auto`) [P].
8. A "run until done" mode: `/goal` in Claude Code (May 11, 2026), Codex (out of experimental May 2026), Cursor (Aug 19, 2026), Antigravity [P, PD §1.5, GAJ §1.4].

**3.4 Read-only tools run in parallel; writes run in sequence.** Claude Code: "Read-only tools ... can run concurrently. Tools that modify state ... run sequentially." [P, CC §2]. Codex runs read-only tools and `readOnlyHint` MCP tools in parallel (0.163.0, 0.134.0) [P, CX §3].

**3.5 Deferred tool loading.** Claude Code `ToolSearch`, Codex `tool_search` (default for MCP since 0.142.2), Copilot `tool_search`, Cursor loads MCP tools on demand, Kiro V3 `tool_load`, Pi MCP in codemode, Factory sends 2 tool definitions instead of 11 [P, CC, CX, GH, CU, GAJ, OT, PL]. [O] This is how harnesses fight the growth of the tool manual (§4.6).

**3.6 Per-model tuning inside the harness.** Claude Code (lean prompt and task tools by model), Codex (`models.json`), Copilot Local (prompt registry plus edit tool per family), OpenCode (per-model prompt files), OpenHands (presets per family), Factory ("tunes its prompts, tool descriptions, and tool-calling mode for each model") [P]. [O] Even the model-agnostic harnesses tune per model; "model-agnostic" means "supports many models", not "treats them the same".

## 4. Where they differ

Placements are [O] judgements built from the cited evidence. Quotes are verbatim from the files, with refuted wording excluded.

### 4.1 Axis: how thick the harness should be

| Thin / delete as models improve | Thick / build around the loop |
|---|---|
| Claude Code, Pi, mini-swe-agent, Amp, Auggie v2, Cursor's prompt trim, OpenAI's Astra guidance | Kiro (specs, Cedar, Lean, Crew), Copilot (Fusion, rubber duck, memory, policy), Devin (VMs, Fusion, DeepWiki), Factory (PTC, routers, Environments) |

Evidence:
- Cherny, May 7, 2025 (older than 6 months): "all the secret sauce, it's all in the model. And this is the thinnest possible wrapper over the model. We literally could not build anything more minimal." [P, CC §8] https://www.latent.space/p/claude-code
- Cherny, Jul 27, 2026: "We unship tools all the time. We delete code in the harness all the time. If you look at the code that's in the Claude Code harness today, almost all of it is about safety and permissions and static analysis." [P, CC §8] https://www.ycrootaccess.com/p/boris-cherny-building-claude-code
- Provencher (OpenAI), Sep 11, 2026: "With more capable models, what used to require a lot of handholding and scaffolding no longer does." [P, CX §8] https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra
- Augment, Aug 14, 2026: "The main learning: subtraction. Fewer tools means less tax on every call, and one good retrieval saves ten turns of exploration." [P, PL §5.2]
- Zechner, Nov 30, 2025 (older than 6 months): "My philosophy in all of this was: if I don't need it, it won't be built. And I don't need a lot of things." [P, OT §6]
- Kiro, Oct 20, 2026: "Try removing before adding. The safest wins are often removals, especially as models get better." [P, GAJ §2.3]
- On the thick side, Kiro: "Ordinary non-exhaustive test suites sample behavior; a proof establishes a universal result for the formal model." (Nov 2, 2026) [P, GAJ §2.3]
- [O] The minimal camp still adds features (Pi added MCP; Claude Code has 33 hook events and mods). What separates the camps is defaults: minimal harnesses ship small and let users add.

### 4.11 Does the harness change outcomes? Same-model evidence (added in round 5b)

All from HE unless noted. HE's verification pass could not reload the official tbench.ai board data, so official Terminal-Bench numbers below are [E] except where marked; vals.ai, paper and vendor-page numbers were re-confirmed.

**The headline figure people cite is wrong.** arXiv 2605.23950 (Zhang et al., May 7, 2026) says: "Under the standardized SEAL scaffold on SWE-bench Pro, Claude Opus 4.5 reaches 45.9%, while under Claude Code the same model reaches 55.4%." [P that the paper says it]. Its source is a Morph aggregator table of self-reported scores (Wayback capture of Apr 3, 2026) [P]. Augment, which ran all three product harnesses itself on the same 731 tasks, reports Auggie 51.80%, Cursor 50.21%, Claude Code 49.75%, with a SWE-Agent baseline of 45.89% taken from Scale's leaderboard (Jan 2026) [P, Auggie figure is a vendor claim] https://www.augmentcode.com/blog/auggie-tops-swe-bench-pro. 55.4% was Opus 4.6's baseline in a Morph post. So SEAL to Claude Code is +3.9 points, not +9.5, and the three product harnesses span 2.05 points [R on 45.9 vs 55.4, HE §1.1]. Round 2 had already caught the same error in round 1 files.

**Controlled evidence: big effects where the harness fixes a real limit.**
- arXiv 2608.26218 (Lewis, Aug 26, 2026), one harness with one change (shorten old tool results and react to stalled work), same weights and tasks: Qwen3.6-35B-A3B went from 43 to 72 solved on SWE-bench Verified with a 20,480-token window (McNemar 34:5, p<0.0001), and from 31 to 72 on SWE-bench Pro at 49k. At 262,144 tokens the effect vanished: 102 vs 101 solved, F2PF (share of target tests fixed) "-0.3 percentage points (95% interval [-4.5, +3.9])" [P, HE §2]. The treatment also used more compute, and only local open-weight models were tested [P]. Abstract: "Because changing the harness changed what unchanged model weights could accomplish, coding-agent evaluations should treat the model and harness together as the tested solver." [P]
- arXiv 2605.23950's own 3x3 grid (GPT-5.4, Kimi K2.6, GLM-5.1; 100 Verified tasks, two runs): changing the harness moved scores 8.5 to 13 points, changing the model 2.5 to 5 points, a ratio the authors call "7.80×" and say they "do not claim ... is universal" [P, HE §1.3]. [O] Caveats: the models were picked because they score alike; 2.5 to 5 points is inside noise at 100 tasks; the weakest harness has no retries, raw errors and accepts empty patches. Most of the H2 to H3 gain came "from closing the verification and recovery loop" [P].

**Independent evidence: small effects between competent harnesses on strong models.**
- Scale's SWE-Bench Pro V2 (arXiv 2610.24206, Oct 16, 2026), GLM-5.3, Kimi K3 and Inkling in mini-swe-agent, Pi and OpenCode on 642 tasks: "the task explains 32% of the variance in solved-or-failed, the model 2.7% and the scaffold 0.3%" [P, HE §6.1]. Spreads 0.9, 1.7 and 7.5 points. The scaffold changed cost: Kimi K3 used 1.3M tokens per solved task under Pi and 2.6M under mini-swe-agent [P]. [O] Open-weight models only, and V2 is near saturation (87% to 99%).
- Terminal-Bench 4.0: the official board has no same-model, different-agent rows; each model appears with one agent [E, HE §4.1]. vals.ai runs every model in bash-only mini-swe-agent [P]. Pairing the two boards, 10 of 16 frontier models land within 3 points of their vendor-harness score; outliers are Grok 4.7 (+8.8 in Grok Build), GPT-6 Sol (+5.0 in Codex) and Qwen3.8 Max (-11.9 in Claude Code, which was not built for it) [P vals data, E official data, O pairing, HE §4.2].
- Effort settings move scores as much as harness choice: Opus 5 in Claude Code goes from 34.8% (low) to 53.9% (xhigh) on Terminal-Bench 4.0 [E, HE §4.1]. The same model and harness (Opus 4.8 with Claude Code) scores 78.88 on the official Terminal-Bench 2.1 board and 69.66 on vals.ai [E official, P vals, HE §4.3].

**Public leaderboards: wide spreads, weak checks.**
- Terminal-Bench 2.0: Opus 4.6 ranges from 58.0 (Claude Code) to 76.4 (Meta-Harness) across nine agents, but only 4.9 points among rows the board flags as verified [E, HE §4.4]. The board's Apr 19, 2026 integrity post: "their agent curls the solution from the internet and includes it in its AGENTS.md. We have rescored those trials to 0." (ForgeCode; rescored, not removed) [P] https://www.tbench.ai/news/leaderboard-integrity-update
- Meta-Harness (arXiv 2603.28052): 76.4 on Opus 4.6, 1.7 points over Terminus-KIRA, the harness it extends, and 1.1 over Capy (75.3), the best reproducible hand-built row in its own Table 7. The paper reports no confidence intervals, and search and evaluation used the same 89 tasks [P, HE §3]. [R] Calling Terminus-KIRA "the best hand-built harness" is wrong.
- SWE-Bench Pro Verified (arXiv 2609.08149): once answer leakage was blocked, GLM-5.2 fell from 78.80% to 57.32% [P, HE §6.2]. It is a paper about reward hacking and bad tasks; the "a third of trials misgraded" figure is a separate Datacurve claim [S].

**Vendor-run head-to-heads (each is a vendor claim).**
- Factory, Terminal-Bench 4, high effort: Opus 5.5 in Droid 65.2%, Cursor 62.1%, OpenCode 62.1%, Devin 59.6%, Claude Code 57.6% [P, vendor claim]. The official board has Claude Code with Opus 5.5 at 64.8% ± 3.1 at max effort [S, third-party mirror]. Factory's margin (+7.6) is about the size of that runner and effort gap [O, HE §5.1].
- GitHub (Jun 25, 2026): Copilot CLI vs Claude Code and Codex CLI on the same models: "These results reflect effective parity, since the differences in either direction are within the variance." For benchmarks under 100 instances, "the best scored run is reported" out of five. Chart alt text: Copilot CLI "performed worse for Sonnet 4.6 and Opus 4.7, but better for GPT models" on SkillsBench [P, vendor claim, HE §5.2].

**What a presenter can say** [O, HE §10]: a score belongs to a model plus a harness plus settings; changing only the harness can move results a lot when it fixes a real limit; for frontier models on well-graded tasks, competent harnesses land a few points apart, often inside the noise; vendor comparisons each favour the vendor. For a Copilot-only bank, the evidence does not support "you lose 10 to 20 points by using Copilot". The bigger measured levers are the ones a team controls: context management on long tasks, verification before finishing, model and effort, and what the agent can reach on the network.

## 5. Philosophies by family

Each paragraph is built from the builders' own words and shipped behaviour. Where the philosophy is inferred from behaviour, it is tagged [O].

**Anthropic (Claude Code).** Stated: do the simple thing first, keep the wrapper thin, and build for the next model. Cherny: "Generally, at Anthropic, we have this product principle of do the simple thing first" (May 2025, older than 6 months) [P, CC §8]. Ben Mann (about Jul 2026): "you have to build something that works 20 or 30 percent of the time now, so that when the next model comes out, it works 80 percent of the time." [P, CC §8]. Cherny (YC, Feb 2026, older than 6 months): "don't build for the model of today, build for the model of 6 months from now" and "never bet against the model" [P\*, auto-captions, PA §1.1], framed as a trade-off: "always always think in terms of this trade-off where where do you actually want to invest" [P\*]. Shipped behaviour matches: per-model prompt ablation, tools removed (Glob, Grep, TodoWrite), `/doctor prompt-audit` to flag instructions written for older models [P]. The 2026 addition is safety by environment: "Design for containment at the environment layer first, then steer behavior at the model layer." [P]. Rejected in their words: RAG for code, elaborate memory architectures, per-action human approval as the main control ("we've found the approach to be fallible") [P, CC §8]. [O] The loop stayed thin while the code moved into safety, permissions and UI.

**OpenAI (Codex).** Stated: delegate like to a teammate while keeping responsibility and permissions separate. "Instructions communicate intent; permissions control access." and "An agent does not share a colleague's lived experience of your organization or responsibility for the outcome." [P, CX §8] https://learn.chatgpt.com/docs/working-with-agents. The harness is pitched as reusable infrastructure: "you can start with Codex instead of inventing a new runtime" (Aug 19, 2026) [P]. Scaffolding should shrink as models improve (Provencher, Sep 2026) [P]. Sottiaux treats the harness as a temporary "crutch" and triages each gap as "a harness change or should this be a model change" (Sep 9, 2026) [P\*, PA §2.2]. Embiricos: "This harness we need to do our best to keep as simple as possible, and then have the right primitives for extensibility, and you let the model orchestrate as much as possible." (Oct 15, 2026) [P, Every, not certified verbatim, PA §2.1]. Ambrosino: "So we do training on the harness now." [P, same caveat]. Shipped behaviour points to tight co-design: per-model settings in `models.json`, code mode forced on for current models, a long prompt tuned for autonomy and writing style [P]. On contributions: "implementation is comparatively straightforward with the help of Codex itself." [P, CX §8]. Rejected: external code PRs, Chat Completions endpoints for custom providers, unsolicited safety checklists in model output [P].

**GitHub / Microsoft (Copilot).** Stated: multi-model, one harness, open edges. "A unified harness lets us ship faster, learn faster, and improve Copilot over time." [P, GH §8]. "A harness should be fast, token-efficient, and predictable for developers." (Basava and Castro, Jun 25, 2026) [P]. "Access to multiple models remains one of Copilot's pillars" (VS Code Wrapped, Oct 28, 2026) [P]. "Developers set the direction, make decisions, and stay accountable for what ships." (Parikh, Oct 28, 2026) [P]. Shipped: Fusion routing, cross-family critics, enforced plan mode, fail-closed managed settings, a server-side semantic index [P]. [O] Tension: the 2025 rationale for open-sourcing said models had reduced "the need for "secret sauce" prompting strategies" [P, GH §8], yet the 2026 default runtime is closed and its prompt is not published. Openness now rests on protocols and MIT SDK clients. Nobody at GitHub or Microsoft has said why: Toub's Sep 16 post and the Oct 28 Microsoft harness post say nothing about licensing [P by absence, PA §4]; issue #83 "Open Source?" on github/copilot-cli has been open since Sep 27, 2025 with no staff reply, and a duplicate (#3241) was closed on Oct 26, 2026 with "duplicate" as the only reason [P]; the CLI licence allows redistribution only "in unmodified form" [P]. Microsoft's pitch is a managed service: "With the Copilot harness, Microsoft runs the agent loop and sandbox, with governance and optimization built in from day one." (Schuchman and Fedorov, Oct 28, 2026) [P, upgraded from P\*, PA §4].

**Cursor.** Stated: build "the factory that creates their software" (Truell, Feb 26, 2026, older than 6 months) [P, CU A8], with "The human role shifts from guiding each line of code to defining the problem and setting review criteria." [P]. Measure on live traffic because evals "often represent 'hard' problems and don't properly reflect the true distribution of user requests" [P]. Lin: "Constraints are more effective than instructions" [P]. Shipped: own models trained inside the harness, trained compaction, a grep index built because "the agents just love to use grep" [P]. Rejected: prohibition-style prompts, shared-file locking for swarms, embeddings for search, prompt-based compaction [P, CU A8].

**Cognition (Devin, Devin Desktop).** Stated: context sharing first, then single-threaded writes with helper agents; evaluate cost per task; isolate by VM. "The open problems are all communication problems." (Yan, Apr 2026) [P]. "We can choose and combine the models best suited to the work, including our own, rather than tie customers to one provider" (Series E, Sep 8, 2026) [P]. "Opus behaves like a micromanager with an intern; Fable is a manager with a capable engineer" (Lee, Jul 13, 2026) [P]. "The industry needs to move from maximizing usage metrics to maximizing outcomes" (Scott Wu, Jun 4, 2026) [P]. Devin Desktop launch: "the work of software engineers is shifting towards agent management." (Wu and Wang, Jun 2, 2026) [P, PA §6]. Retrieval is a fast subagent with a "carefully restricted tool set", "co-designed" with the model, returning file and line ranges instead of summaries because "A fast model summary can draw wrong conclusion and mislead the smart model." (SWE-grep, Oct 2025, older than 6 months) [P, PA §6]. SWE-2 (Sep 10, 2026) reports public scores where they exist and otherwise runs each model in "the harness for which it was primarily developed" [P; R on the broader "each model is evaluated in its home harness"]. No edit-format rationale is published. Rejected: unstructured swarms, containers as the isolation boundary [P].

**Google (Antigravity, Gemini CLI).** Stated: co-develop product, harness and model; agents own the surface. "flips the paradigm of agents being embedded within surfaces to one where the surfaces are embedded into the agent." (Nov 18, 2025, older than 6 months) [P, GAJ §1.5]. Rejects both extremes of visibility ("Neither engenders user trust") and remote-only agents without feedback [P]. Varun Mohan at I/O (May 19, 2026): "Gemini 3.5 Flash having been optimized with the Antigravity harness." [P, manual captions, PA §3]. The I/O developer keynote says the same harness runs Gemini Spark, Google's coding agent and AI Studio (Logan Kilpatrick, 00:38:41) [P]. No 2026 Google essay on harness mechanics (tools, edit format, prompt) was found [P by absence, PA §3]. On consolidation: "we can serve you best by pouring our energy into a single product built for today's multi-agent reality." (May 19, 2026) [P]. [O] Shipped behaviour shows product churn as policy: three coding products restricted or retired in six months.

**Amazon (Kiro).** Stated: specs before code, and deterministic checks around the model. Brooker's "super prompt" and "the specification tames the chaos of prompt-driven vibe coding on large code bases" [P, GAJ §2.4]. On self-improvement: "Models can propose changes, but we use deterministic code to accept or reject them." and "We judge an agent experiment first by what it rejects." [P]. On architecture: "The client owns how the user interacts with the agent and how it presents the agent's work." [P]. Shipped: Cedar permissions, Lean proofs (70 of 96 properties proved), spec files [P]. Rejected: ad-hoc prompting on large codebases, library-shaped harnesses, self-graded improvement loops [P].

**JetBrains (Junie, Air).** Stated: multi-vendor, IDE intelligence, verification as the bottleneck. "AI can produce code. Organizations still have to produce software." "An agent will not get the call at 3:00 am when something breaks." "Standardizing on one AI vendor today means making a multi-year commitment in a market that won't look the same next quarter." (Skrygan, Sep 22, 2026) [P, GAJ §3.4]. Junie: "When something goes wrong, most coding agents add log statements. Junie opens the debugger." [P]. Rejected: single-vendor lock-in, agents bolted into chat, println debugging [P].

**Open-source minimalists (Pi, Aider, mini-swe-agent).** Stated: build only what you need, control the context. Zechner: "Exactly controlling what goes into the model's context yields better outputs, especially when it's writing code." [P, OT §6]; "Set yourself limits on how much code you let the clanker generate per day, in line with your ability to actually review the code." (Mar 25, 2026, older than 6 months) [P]. Gauthier's edit-format principle: "SIMPLE - Choose a simple format that avoids escaping, syntactic overhead and brittle specifiers like line numbers or line counts." (2023, older than 6 months) [P]. Pi's MCP reversal (Sep 29, 2026) kept the small defaults: Ronacher, "We have mixed feelings about MCP, but some uses of it are responsible, and the baseline fits reasonably well into pi." [P, OT §6].

**Open-source platforms and foundations (OpenCode, Goose, OpenHands, Cline, Zed).** Stated: provider-agnostic, inspectable, hackable. OpenCode (2025 README, older than 6 months): "As models evolve the gaps between them will close and pricing will drop so being provider-agnostic is important." [P, OT §3]. OpenCode 2.0 note (unsigned, "Anomaly", Oct 12, 2026): "The latest batch of models are incredibly good at orchestration and it is important for harnesses to let them express the full extent of that capability."; nearly every feature is now one of "80+" internal plugins [P, PA §5]. Goose governance: "Our goal is to make goose the most hackable agent available." [P]. OpenHands: "Agent infrastructure should not be a black box." (Greene, Jun 16, 2026) [P, PL §1.8]. Cline: "Cline's original harness was designed in mid-2024 around Claude 3.5 Sonnet," "The legacy harness isn't bad code. It's a period piece." (Rizwan, Sep 2, 2026) [P, OI §1.8]. Zed: "LLMs automate typing, not thinking." and "Treat the code it writes like a PR from an external contributor." (Maki, Jan 23, 2026, older than 6 months) [P, OI §5.7]. Goose on benchmarks: "We want enough failures left on the table to see what support the agent is missing." (Osinga, Jun 17, 2026) [P, OT §4].

**Commercial platforms (Amp, Factory, Augment).** Amp states it builds for the current frontier and deletes the rest: "build for what the frontier models can do now, in 2026, and what they will be able to do in the future. Do not build for what once was." (Neo, May 6, 2026) [P, PL §3.8]. Factory: "We believe the best agent harness is one built for every model" and a set of engineering principles ("Budget every token, and keep large tool results in files. Grow the request by always maintaining the prompt cache.") [P, PL §4.9]. Augment: subtraction, and "simplicity means your developers never have to worry about whether they're on the right one" (model) [P, PL §5.4]. Warp (Zach Lloyd, Sep 5, 2026): "The Inference Layer should support running any model and any agent", "you should have at least one harness that supports open-weight models like Warp Agent or OpenCode, plus the ability to run the main model harnesses from the model labs directly", and "No external provider should get to train on this data. ZDR is a must." [P, PA §7]. Kilo (Turcotte, Apr 21, 2026, older than 6 months): "The IDE is not over. Far from it, actually." [P, PA §7].

**Enterprise-first vendors (Tabnine, IBM, Mistral, GitLab, Atlassian).** Stated: run inside the customer's walls, with guardrails before speed. Tabnine: "a fully private, organization-aware AI coding agent designed to run entirely within your environment" [P, EH §A1]. IBM (Apr 28, 2026, older than 6 months): "Fast AI without the right guardrails is not progress." and "model capability alone isn't enough" [P, EH §A4]. Mistral: "Intelligence you own, not rent." [P, EH §A8]. Atlassian, on folding Rovo Dev into Jira: "our focus on delivering AI where teams already work." [P, EH §A3]. [O] Shipped behaviour: these vendors compete on deployment and governance and increasingly borrow the harness itself (Tabnine on OpenCode, GitLab on Anthropic's sandbox runtime).

**Commentators.** Karpathy (Sequoia, Apr 29, 2026, older than 6 months, 00:16:06): "agentic engineering is about preserving the quality bar of what existed before in professional software." [P\*, auto-captions, PA §8]. On No Priors (Mar 20, 2026) he calls Claude Code and Codex "agent harnesses" [P\*]. He has not proposed a harness design philosophy [O].
