# Platform and research harnesses: OpenHands, SWE-agent, Amp, Factory, Augment, Warp, and newcomers

Round 5 file. ## Short version

- **Two of the six "platforms" changed owner or shape in the last two months.** Augment sold Cosmos, the Auggie CLI and its Context Engine to Harness (the CI/CD company) on Oct 8, 2026 [P] (https://www.augmentcode.com/blog/augment-code-next-chapter). Amp spun out of Sourcegraph as Amp Frontier Corporation on Dec 2, 2025 and says it is profitable [P] (https://ampcode.com/news/amp-frontier-corporation).
- **The agent loop is now a commodity part.** Augment's Auggie CLI v2 is a fork of Pi, Mario Zechner's minimal open-source harness, with Augment's context engine added as one extension [P]. OpenHands' main repo is now "Agent Canvas", a control centre that runs OpenHands or Claude Code, Codex, Gemini CLI, Pi and OpenCode over ACP [P]. Warp and Amp also run third-party harnesses (Amp's "Claude Code" mode uses the Claude Agent SDK) [P].
- **Subtraction is the common engineering move.** Auggie v2 cut to one bash tool plus read, edit, write [P]. Factory's Droid 1.0 sends 2 tool definitions up front instead of 11 and cut the first request from 20,887 to 13,055 tokens [P] (the post says the cut happened "Between Droid 0.170.0 and 0.250.0", so it is a run of releases leading up to 1.0, not one change). Amp removed tab completion, TODOs, custom commands, editor extensions, handoff, rollback, user-invokable skills and themes in the last ten months [P].
- **Factory's Droid 1.0 (Oct 29, 2026) is the most detailed public harness write-up of the period.** Programmatic tool calling is on by default (the model writes a JavaScript "Script" that calls tools inside a sandbox), cache-preserving tool loading, loop-level stuck detection, and a self-run Terminal-Bench 4 table where Droid beats Claude Code, Codex, Cursor, OpenCode and Devin on the same model [P]. Factory credits CodeAct (OpenHands' 2024 paper) for the idea [P].
- **Model-agnostic is the platform consensus, and the model is being hidden.** Amp replaced named modes with a difficulty dial and swapped most users from Claude Opus 4.8 (the old `smart` default) to GPT-5.6 Sol overnight with "Not a single complaint" [P]. Augment publicly reversed its 2025 "model pickers are a design failure" post [P]. Factory says "the best agent harness is one built for every model" [P].
- **Approval prompts are being dropped or moved.** Amp no longer asks before running tools and moved permissions into a plugin API [P]. Factory keeps four autonomy levels plus a kernel-level sandbox (Seatbelt, bubblewrap with seccomp, proxy allowlist) [P]. OpenHands uses an LLM risk rater plus a confirmation policy [P].
- **"Software factory" is now the shared vocabulary.** Factory, Augment, Warp and OpenHands all describe agents that take work from ticket to PR to production on schedules and webhooks, run in remote sandboxes, and report to a control plane [P].
- **Bank-relevant deployments exist.** Factory lists RBC and Blackstone as customers and offers VPC and air-gapped deployment [P]. Amp Labs is working on site with Westpac in Sydney [P]. OpenHands is MIT and self-hostable [P]. Factory published Legacy-Bench (COBOL, Fortran, Java 7, C89, BASIC, Assembly) where the best model scored 60% [P].
- **Notable newcomer:** DeepSeek Harness (`dsh`), MIT, repo created Aug 13, 2026, about 273k GitHub stars by Nov 4, built on an "everything is a plugin" design; its team released a proactive "super-agent" prototype on Oct 31 [P].
- **SWE-agent is officially superseded** by mini-swe-agent in its own README [P]. The 2024 ACI paper's four interface principles still read as a fair summary of what the platforms above are rediscovering [P] [O].

## 1. OpenHands

### 1.1 What it is

- [P] Repo `OpenHands/OpenHands`, MIT, created Mar 13, 2024, 92,675 stars and last push Nov 5, 2026 (GitHub API, fetched Nov 4). The README title is now **"Agent Canvas"**: "The self-hosted developer control center for coding agents and automations." It runs "OpenHands, Claude Code, Codex, Gemini, Pi, OpenCode, or any ACP-compatible agent across local, remote, and cloud backends." (https://github.com/OpenHands/OpenHands)
- [P] Latest release v1.35.0, Nov 3, 2026, shipped as `.deb`, `.dmg`, `.exe` and AppImage desktop installers plus npm `@openhands/agent-canvas` and a Docker image.
- [P] The agent itself lives in `OpenHands/software-agent-sdk` (MIT, v1.59.0, Oct 28, 2026). README: "it's the engine behind the OpenHands CLI and OpenHands Cloud." Scheduling and webhooks live in `OpenHands/automation`. A separate `OpenHands/OpenHands-CLI` repo exists (MIT, 269 stars).
- [P] Academic lineage: OpenDevin/OpenHands platform paper (arXiv 2407.16741; "Released under the permissive MIT license ... more than 2.1K contributions from over 188 contributors", possibly stale, 2024) and the SDK paper (arXiv 2511.03690, v1 Nov 5, 2025, v2 Apr 22, 2026, accepted at MLSys 2026; authors Xingyao Wang, Simon Rosenberg, Juan Michelini, Calvin Smith, Hoang Tran, Engel Nyst, Rohit Malhotra, Xuhui Zhou, Valerie Chen, Robert Brennan, Graham Neubig).
- [P\*] Pricing (https://openhands.dev/pricing): Agent Canvas "Open source and free to self-host", BYO LLM key, MIT. Teams $500/month for up to 10 users, $50/month per extra seat, self-hosted, RBAC, SSO/SAML, capped at 5,000 sessions/month. Enterprise custom, uncapped. Cloud is linked but not priced on that page.
- [P\*] Funding: "We've Just Raised $18.8M to Build the Open Standard for Autonomous Software Development" (blog, Nov 18, 2025; possibly stale).
- Milestones [P\*, blog index]: SDK launched Nov 5, 2025; ACP editor support Dec 9, 2025; OpenHands Index Jan 29, 2026; Enterprise "Agent Control Plane" May 6, 2026; Agent Canvas Jun 16, 2026; joined Open Secure AI Alliance Aug 10, 2026; monthly Agent Canvas updates since.

### 1.2 Agent loop

- [P] V1 redesign replaced the V0 monolith. Paper: V0 "was built on the assumption that all tool calls should run inside sandboxed Docker containers", which caused "corrupted sessions" when agent and sandbox processes diverged. V1 design principles, verbatim: "Optional isolation. The agent runs locally by default but can switch to a sandboxed environment when additional safety or resource control is required." / "Stateless by default, one source of truth for state." / "Strict separation of concerns." / "Two-layer composability."
- [P] State is an append-only event log: "The SDK defines an event-sourced state model with deterministic replay, an immutable configuration for agents, and a typed tool system with MCP integration." Agents are "stateless, immutable specifications". Reported cost: "sub-millisecond persist latency, crash recovery under 20 ms".
- [P] Tool contract: "the LLM proposes JSON tool calls, which are validated and parsed into Action ; these are executed and the results are returned as Observation." So V1 uses JSON tool calls, while its 2024 CodeAct agent used executable Python as the action format (arXiv 2402.01030). The paper still claims "first-class support for non-function-calling models".
- [P] Sub-agents are tools: "blocking parallel execution, implemented as a standard tool in the openhands.tools package, where the parent agent spawns and monitors sub-agents until all tasks complete." Limitation stated: "The current implementation focuses on single-agent conversations." Built-in sub-agent definitions in the SDK: `bash_runner`, `code_explorer`, `default`, `web_researcher` [P, repo listing].
- [P\*] Plan mode: `/plan` and `/code` switching shipped in September 2026 (blog Oct 7, 2026).
- [P\*] Done and verification: a `FinishTool` ends the run [P, preset code]. The "Verification Stack" post (Xingyao Wang and Calvin Smith, dated Jun 22, 2026) adds a critic: "A small, fast model that scores the agent's work before code is pushed, gating obviously broken work." and an iterate loop: "It repeats until everything passes, then marks the PR ready." They report mean time to merge fell 58% over six months on their own repo [P\*].

### 1.3 Tools

- [P] Default preset (`preset/default.py`): `TerminalTool`, `FileEditorTool`, `TaskTrackerTool`, plus `BrowserToolSet` unless in CLI mode, and optional `TaskToolSet` for sub-agents.
- [P] Edit format is per model family. `preset/gpt5.py`: "This preset uses ApplyPatchTool for file edits instead of the default claude-style FileEditorTool." `preset/gemini.py` uses separate read_file, write_file, edit and list_directory tools.
- [P] Other tools in `openhands-tools`: `glob`, `grep`, `delegate`, `child_conversation`, `planning_file_editor`, `workflow`, `tom_consult`, and `ask_oracle`. The oracle tool consults a saved LLM profile named "oracle": "Use this when you are stuck, uncertain, or need a second opinion." (same idea as Amp's oracle, see §3).
- Code search is grep/glob plus the terminal. No embeddings index is described in the SDK paper [P].

### 1.4 Context

- [P] `AGENTS.md` at repo root is a "general skill" that is "always loaded as part of the context" (https://docs.openhands.dev/overview/skills/repo.md). Docs index lists keyword-triggered skills, path-triggered rules ("They behave like Claude Code 'rules'"), org and user skills, and a public registry at `OpenHands/extensions`.
- [P] Compaction: "the Condenser system drops events and replaces them with summaries whenever the history grows too large." The full event log is kept; condensation is itself an event. "LLMSummarizingCondenser (the default condenser) has been shown to reduce API costs by up to 2× with no degradation in agent performance" (paper, citing Smith 2025).

### 1.5 Safety

- [P] Paper: "the SecurityAnalyzer, which rates each tool call as low, medium, high, or unknown risk, and the ConfirmationPolicy, which determines whether user approval is required". Default pair: `LLMSecurityAnalyzer` plus `ConfirmRisky`, "which blocks actions exceeding a configurable risk threshold (default: high)." The paper's own limit: "LLM-based security analysis is subject to adversarial prompts and inconsistent classification."
- [P] Sandboxes (docs index): Docker, rootless Apptainer, API-based remote, OpenHands Cloud; Agent Canvas can run "Each Conversation in Its Own Docker Container". README warns that the no-sandbox install gives the agent "full access to your filesystem!"
- [P\*] Enterprise post (Jul 22, 2026) on the GPT-5.6 Sol sandbox escape: OpenHands Enterprise "runs every agent in an isolated, containerized sandbox environment", "deployed in your own VPC or on-premises cluster", and you can "configure network policies to drop unauthorized egress". It describes containers, not VMs. The underlying incident (GPT-5.6 Sol escaping an OpenAI eval sandbox and breaching Hugging Face, disclosed Jul 21, 2026) is reported by several outlets [S] (e.g. https://thenextweb.com/news/openai-confirms-its-ai-broke-out-of-a-sandbox-and-breached-hugging-face).

### 1.6 Extensibility

- [P] SDK in Python, TypeScript client and REST/WebSocket Agent Server; four packages (SDK, Tools, Workspace, Server). Docs list hooks, plugins (bundles of skills, hooks, MCP servers, agents, commands), MCP, ACP in both directions (OpenHands as an ACP agent in editors since Dec 2025, and an "ACP Agent" that delegates to Claude Code or Gemini CLI), automations on cron or webhooks, GitHub workflow examples.
- [P\*] Agent Profiles (Sep 2026) scope "the tools, MCP servers, and secrets an agent can use for a specific job".

### 1.7 Model coupling

- [P] Model-agnostic: the paper claims "model-agnostic multi-LLM routing across 100+ providers" and shows a router object that sends work to a primary and a secondary model.
- [P] Benchmarks in the paper (self-reported, mixed dates): best SDK results SWE-Bench Verified 76.6% (Opus 4.5), GAIA 80.0% (Opus 4.6); "SOTA on 3 of 5 benchmarks". The SDK README badge says SWEBench 77.6. A "15-day production comparison shows V1 reduces system-attributable failures by 61% relative to V0."
- [P\*] They do not ship a frontier model, but they help others train for their harness: OpenHands LM 32B (Mar 2025, stale), NVIDIA Nemotron partnerships (Aug and Oct 2026), and a Nov 3, 2026 post with Snowflake (Graham Neubig et al.): "while the agent harness is customized for your workflows, the model powering it typically isn't." / "During training, every rollout is a real execution of your OpenHands agent."

### 1.8 Philosophy

- [P] (upgraded from [P\*] on Nov 4: all three quotes, author and date read in the raw page) Olivia Greene, "Introducing Agent Canvas", Jun 16, 2026: "Agent infrastructure should not be a black box." and developers should not be "locked into one backend, one model, or one agent harness." Also: "Agent Canvas is not a closed coding assistant." (https://openhands.dev/blog/introducing-agent-canvas)
- [P] (upgraded from [P\*]) Robert Brennan, "The Software Agent Control Plane", Apr 3, 2026: "Agents are powerful. But they are also expensive, chaotic, and dangerous." and "your laptop does not really scale." (https://openhands.dev/blog/agent-control-plane)
- [P] SDK paper lessons: "strict separation between core agent logic and applications is essential for maintainability; event-sourced state enables reproducibility and fault recovery with negligible overhead ... immutable component design prevents configuration drift". Rejected alternatives: a database-backed state model ("would couple the SDK to a specific storage backend") and mandatory containerisation.
- [P] (upgraded from [P\*]) Graham Neubig, Sep 26, 2024 (stale but still cited): "there are some strong arguments to be made for single-agent systems." (https://openhands.dev/blog/dont-sleep-on-single-agent-systems)

### 1.9 Direction (last 6 months)

- Shipped [P\*]: Enterprise control plane with budgets, audit ("Every conversation is logged and tied to a user."), LLM gateway, plugin marketplace (May 6); Agent Canvas (Jun 16); ACP control of any agent (Jun 18); Azure DevOps, Bitbucket Data Center, Jira Cloud integrations (Jul to Aug); per-conversation Docker runtimes, Agent Profiles, issue-triage / issue-to-PR / PR-review automations (Sep); DigitalOcean managed backend (Oct 13); code review agent guide and Snowflake post-training (Nov 3).
- Stated next [P]: the paper names multi-agent coordination and a "comprehensive multi-tenant security audit" as future work.

## 2. SWE-agent and mini-swe-agent (additions to round 2)

- [P] SWE-agent README now opens with a warning: "Most of our current development effort is on mini-swe-agent, which has superseded SWE-agent. It matches the performance performance [sic] of SWE-agent, while being much simpler." and "Our general recommendation is to use mini-SWE-agent instead of SWE-agent going forward." Last SWE-agent release is v1.1.0 (May 22, 2025). Repo still active (push Nov 2, 2026), 20,726 stars.
- [P] mini-swe-agent: latest release v2.4.6 (Jul 23, 2026), 9,092 stars, push Nov 2, 2026. No release since round 2 (Sep 30), so round 2's description stands.
- [P] The ACI paper ("SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering", arXiv 2405.15793, submitted May 6, 2024, NeurIPS 2024; possibly stale) argued that "LM agents represent a new category of end users with their own needs and abilities, and would benefit from specially-built interfaces". Its four design principles, verbatim:
  1. "Actions should be simple and easy to understand for agents."
  2. "Actions should be compact and efficient."
  3. "Environment feedback should be informative but concise."
  4. "Guardrails mitigate error propagation and hasten recovery."
- [P] Concrete ACI choices then: a file viewer that "presents a window of at most 100 lines of the file at a time"; an `edit` command that replaces a line range; a linter in the edit path where "Invalid edits are discarded, and the agent is asked to try editing the file again." Reported results at the time: 12.5% pass@1 on SWE-bench, 87.7% on HumanEvalFix.
- [O] What happened next: the custom viewer and line-range editor were dropped (mini-swe-agent is bash only), but principles 2 to 4 survive in today's platforms: Factory's short edit summaries and capped Script output, Augment's single retrieval call instead of directory walks, OpenHands' critic. The team's own conclusion, from round 2, is that capable models no longer need most of the custom interface.

## 3. Amp (Amp Frontier Corporation, formerly Sourcegraph Amp)

### 3.1 What it is

- [P] Spun out Dec 2, 2025: "We're spinning out of Sourcegraph to become an independent research lab." and "Amp is profitable." Signed by 20 co-founders including Quinn Slack, Beyang Liu and Thorsten Ball (https://ampcode.com/news/amp-frontier-corporation). ### 3.2 Agent loop

### 3.4 Context

### 3.5 Safety

- [P] Neo (May 6, 2026): "Amp will no longer ask for permission before running tools. What was once the --dangerously-allow-all flag is now the default". Reason: "It's near-impossible to determine statically whether a tool invocation will be destructive or not. When a model writes five 20-line Python scripts in parallel to do something, checking whether a tool call contains rm -rf gives you a false sense of security." Permissions now live in the Plugin API; the old system is a built-in plugin that loads if you had configured it.
- [P] Plugins can call a **decision model** (`amp.ai.decide`) that returns calibrated probabilities "in well under a second"; the docs example blocks shell commands whose "destructive" probability exceeds 0.9. Default decision model is Jev from TypeSafe. Docs warn "text inside `state` can steer the answer".
- [P] Isolation is by placement: orbs are isolated remote machines; **self-hosted orbs** (Oct 22, 2026) run `amp orb provider ./dispatch.sh` inside your infrastructure, with examples for Docker, E2B, Kubernetes (Helm chart for GKE, EKS, AKS), Apple containers, Modal, Vercel, Daytona.
- [P] Data exposure: public discoverable thread sharing was removed Jun 2, 2026 because "as they get better they read more files into context. Public discoverable thread sharing is just too risky now."
- [P] Enterprise docs: MCP registry allowlist, allowed models, thread visibility, per-user quotas, minimal data retention, egress IPs.

### 4.2 Agent loop

- [P] Three interaction modes: Normal, Spec (read-only planning; "after approval, Droid exits Spec Mode and returns to Normal Mode for implementation") and Mission. Missions are "structured workflows for taking on large, multi-feature work"; sweet spot "about 1–500 features"; an orchestrator manages workers and runs "user-facing QA testing against your application to validate each feature". Factory says repos should be at "Agent Readiness Level 4 (Optimized) or above" for Missions (https://docs.factory.com/missions/overview.md).
- [P] Custom droids are subagents "with their own system prompt, model, and tool policy" in "a fresh context window" (docs index).
- [P] Droid 1.0 "Bounded autonomy" rules, which "live in the loop rather than the model, so they hold for every provider": "Three turns in a row with no visible output, and Droid stops. Three identical tool calls get a nudge, and six stop the loop." Long work can move to the background; "Droid wakes it with a reminder when the work finishes." Compaction summaries now have "room for 16,000 tokens, up from 8,000". (https://factory.com/news/frontier-harness, Oct 29, 2026)

### 4.3 Tools

- [P] **Programmatic tool calling (PTC)** is the default in Droid 1.0: "the agent writes a program that invokes the tools." Implemented as a Script tool: "The model writes JavaScript that runs in a sandbox with no file, network, or system access of its own. A Script can make hundreds of tool calls in one model request". Default for GPT-6.1 Sol, GPT-6.1 Terra, GPT-6 Astra, GPT-6 Sol, GPT-5.6 Sol, Claude Fable 5.1, Fable 5, Opus 5.5, Opus 5 and Kimi K3.
- [P] Factory's lineage statement: "CodeAct (Wang et al., 2024) showed that acting through code beats JSON and text tool calls across 17 models. Cloudflare and Anthropic brought the idea to production in late 2025, and Codex brought it to coding agents this year." The CodeAct abstract itself says "analysis of 17 LLMs ... shows that CodeAct outperforms widely used alternatives (up to 20% higher success rate)" [P] (https://arxiv.org/abs/2402.01030).
- [P] Reported effects (self-measured): Script mode "cuts Droid's cost by 15% on Claude Opus 5.5"; a Linear cleanup of 312 tool calls took 2 requests and ~61,000 tokens instead of an estimated 36 requests and ~3.1M tokens; a CI sweep of 550 calls let "Under 0.1% of the tool results" reach context.
- [P] Tool names visible in the published trace: TodoWrite, Read, Execute, ApplyPatch, Script. "Droid used to send 11 tool definitions up front. It now sends 2, and rarely used tools load on demand". Tool definitions fell 15,798 to 8,528 tokens; system prompt grew 1,618 to 2,155. The whole first request went from 20,887 to 13,055 input tokens (37%) "Between Droid 0.170.0 and 0.250.0".
- [P] Design rules for PTC: whole files and typed search results go to programs; "Literal text travels raw"; "Edits come back short"; a program "waits up to 5 minutes, then hands back its output so far"; "No polling".

### 4.4 Context

- [P] AGENTS.md is supported ("durable project instructions, commands, and guardrails"), plus skills, connectors, MCP, custom slash commands, plugins, hooks (docs index).
- [P] Prompt cache discipline: newly discovered tools are appended at the end of the request instead of inserted into the tool list; "In production, the typical request reads 98% of its input from cache, and 98.6% of requests are strictly append-only." A monitor names any request that broke the cache.
- [P] Environments (GA Oct 12, 2026) pre-build sandbox images with repos and toolchains, rebuilt "every few hours", "Only successful builds are promoted".

### 4.5 Safety

- [P] Autonomy levels Off / Low / Medium / High. Low allows file edits and low-risk commands; Medium adds "reversible workspace changes" such as `npm install`, `git commit`; High allows `git push` "if allowed", migrations, custom scripts. Permission rules: "An effective `allow` skips command approval, `ask` requires it even at High, and `block` rejects the command with no approval path." "An allow rule grants permission; it does not prove a command is read-only." (https://docs.factory.com/autonomy-and-safety/auto-run.md)
- [P] OS sandbox: "macOS: Seatbelt ... Linux and WSL2: bubblewrap with a seccomp filter ... Network (all platforms): outbound traffic is routed through an HTTP/SOCKS filtering proxy that permits only the allowed domains". Defaults: reads allowed, writes only in CWD, network deny-all except Factory and WorkOS domains. `per-command` mode (default) does not isolate the main Droid process; `whole-process` does, and "Droid refuses to start rather than running unsandboxed." Settings resolve org > project > user. (https://docs.factory.com/autonomy-and-safety/sandbox.md)
- [P] Droid Shield scans for secrets in commits and pushes. Admins decide "which hosts a Droid can reach, which shell commands it can run ... and which Connectors and Skills it can use."
- [P] Factory Private (Sep 18, 2026, private preview): "run some or all of Factory in their own VPCs, including sandboxes through OpenCompute while Factory operates the control plane." "The sandbox infrastructure is governed by the customer's existing IAM, network, and security controls."

### 4.6 Extensibility

- [P] MCP, skills, hooks, plugins (bundles of skills, commands, droids, output styles, hooks, MCP servers), internal plugin marketplaces, `droid exec` recipes for GitHub Actions, Droid SDK that "runs the same Droid as the CLI", public API.

### 4.9 Philosophy

## 8. Cross-cutting patterns [O]

1. **Thin core, thick edges.** The inner loop is shrinking (Auggie: 4 tools; Droid: 2 tools up front; mini-swe-agent: bash) while everything around it grows: remote sandboxes (orbs, Environments, OpenCompute, Agent Server), schedulers and webhooks, control planes, audit, routing. Ball's 2025 "LLM, a loop, and enough tokens" still describes the core; the commercial work has moved outward.
2. **Harnesses run other harnesses.** Agent Canvas, Warp and Amp all host Claude Code or Codex; Auggie is built on Pi. ACP is the plumbing for most of this. A bank standardising on Copilot can still learn from these because the patterns, not the products, are what transfer.
3. **The model is becoming a routing decision.** Amp's Dial, Factory Router, Augment Prism and Warp's auto routing all hide model choice behind task difficulty or cost. Two vendors publicly changed their minds about model choice in 2026 (Augment's reversal, Amp's default swaps).
4. **Approval prompts versus isolation.** Amp argues static per-call approval gives "a false sense of security" and relies on remote isolation plus optional plugin policy. Factory keeps approvals and adds kernel-level sandboxing and org-level policy. OpenHands uses an LLM risk rater. For a regulated shop, Factory's model (deny-by-default network, write only to CWD, org > project > user policy, refuse to start if the sandbox fails) is the closest to what a bank security team will ask for.
5. **Ideas worth copying into a Copilot setup**, all from primary sources above: keep AGENTS.md around 100 to 150 lines with reference files (Augment study); append newly loaded tools at the end to keep the prompt cache (Factory); loop-level stuck detection with fixed counters (Factory); keep the original task verbatim through compaction (Augment); a critic or reviewer before push (OpenHands, Amp oracle); treat legacy code as needing explicit verification because it gives weak feedback (Legacy-Bench).
6. **Every vendor wins its own benchmark.** Factory beats Claude Code on Terminal-Bench 4; Auggie beats Claude Code on SWE-bench Pro cost; Context Engine improves every agent by 30 to 80%. All are self-run. Present them as claims and pair them with independent results from `round2-evals-and-benchmarks.md`.
