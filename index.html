working definition

AI engineering, defined for this talk

AI engineering = harness engineering + context engineering + memory engineering + prompt engineering.

Covered here

  • Harness — the tooling around the model: instructions, agents, MCP, hooks
  • Context — what the model sees, and when
  • Memory — what survives between sessions
  • Prompt — what you actually say

Deliberately out of scope

  • RAG — the retrieval arm of context engineering; same principles

first principles

A neuron is a weighted opinion

  • Take numbers in, multiply each by a weight, add them up, squash the result
  • That's it. That's the neuron.
  • Stack them in layers: a multi-layer perceptron
  • The weights are the parameters — "405B parameters" = 405 billion of these knobs

A neural network is one function: numbers in → numbers out. Everything else is plumbing.

inputs weights x₁ ──▶ ×w₁ ─┐ x₂ ──▶ ×w₂ ─┼─▶ Σ ─▶ squash ─▶ out x₃ ──▶ ×w₃ ─┘ the knobs training turns
Deliberately unglamorous. "Weighted opinion" is the phrase to keep using: each neuron votes on a tiny question, layers of votes become judgment.

what training actually does

Guess. Measure the wrongness. Nudge every knob. Repeat.

  1. Guess: run the input through, get an output
  2. Score it: one number for how wrong (the loss)
  3. Nudge: compute, for every knob, which direction reduces the wrongness — turn all of them a hair (backpropagation)
  4. Repeat: trillions of times, on trillions of examples

Training doesn't store the examples — it compresses their regularities into the knobs. That's why one function can complete code it has never seen.

Kill the "it's a database" mental model here, gently — it decides how people reason about everything later (hallucination, context, why instructions files work).
scores → probabilities

Softmax and the temperature dial

A language model's last layer outputs a score for every token it knows. Softmax turns scores into probabilities — that's the whole trick.

  • Temperature ↓ — sharpen: always take the favorite. Safe, boring, repetitive.
  • Temperature ↑ — flatten: give the long shots a chance. Creative, and eventually unhinged.

Try it live in Transformer Explainer (Act 2) — it has the actual slider.

scores T = 0.2 T = 1.5 " the" 9.1 ████████ 92% ███ 34% " a" 7.3 █ 7% ██ 27% " its" 5.0 · 1% ██ 21% " kiwi" 2.2 · 0% █ 18% same engine, different dial
"The model is not choosing a word. It's pricing every word it knows, and then we gamble according to the prices." Temperature = how honest the casino is.

consequences

Why smart models fail dumb tests

Counting letters

"strawberry" arrives as one or two opaque chunks. Asking for the r's is like asking you how many times the letter e appears in a word you've only ever heard spoken.

Arithmetic

"1234567890" isn't a number — it's chunks like 123·456·7890, split by frequency, not place value. Long division over that is a miracle when it works.

These aren't intelligence failures — they're eyesight failures. Reasoning models patch them by thinking in steps; the eyesight never changed.

"Eyesight, not intelligence" is the line that sticks. Warn honestly: current reasoning models DO count the r's fine now — they spell it out in scratch work first. The failure mode is real; the party trick is patched.
meaning as geometry

Every token becomes a point in space

  • Each token maps to a vector — hundreds of numbers, learned, not assigned
  • Similar meaning ends up nearby: king/queen, Paris/Rome, try/catch
  • Directions mean things: king − man + woman ≈ queen
Embedding Projector — real embeddings, rotatable in 3D open in new tab

Optional live beat: search a word, look at its neighbors. Meaning with no dictionary anywhere — just geometry, learned from co-occurrence.

Keep short. The point that matters downstream: "the model thinks in this space, not in words" — sets up attention and why context works at all.
order

Position must be stamped on

Attention reads the whole context at once — to it, "dog bites man" and "man bites dog" are the same bag of tokens.

  • Fix: mix a position signature into each token's vector before it enters
  • Each slot gets a distinct stamp; nearby slots get similar stamps
  • The network learns to read the stamp exactly as much as it needs to

That's the honest intuition level. The gorgeous sinusoid math is in the appendix — it's depth, not prerequisite.

One slide, on purpose. If someone pushes: "postmark on the envelope" — content plus where-it-was-mailed-from, in one vector. Appendix has RoPE etc.
the mechanism that changed everything

Attention: every token interrogates every other

For each token, in parallel: "of everything before me, what matters to what I'm about to be?"

  • "bank" pulls on "river" — or on "loan" — and becomes a different vector accordingly
  • Meaning stops being per-word and becomes per-word-in-this-sentence
  • Dozens of attention heads per layer, each learning its own question — grammar, coreference, code scope…
  • And it's all matrix math — perfectly parallel, perfect for GPUs. That, as much as the cleverness, is why transformers won.
The two-part claim matters: attention won on QUALITY (context-dependent meaning) and on THROUGHPUT (parallel training). RNNs read one word at a time; transformers read the whole page at once, so you can feed them the internet. Next slide is the live proof.

act 03 · scale

The absurd arithmetic
of one token

Not the training run. Not the answer. One single token of output. The numbers here are cited, and they should feel wrong.

This act is pure vertigo. Slow delivery, let numbers sit. Using Llama 3.1 405B throughout because its numbers are OFFICIAL — frontier labs publish nothing, so honest numbers beat impressive ones.
the unit

What one token costs

Llama 3.1 405B — open weights, every parameter public. Each parameter does one multiply-add per token: 2 × 405 billion.

810,000,000,000 floating-point operations, per token, forward pass only — roughly one token ≈ three-quarters of a word

2N rule: Kaplan et al., Scaling Laws for Neural Language Models (2020) · params official: Meta, arXiv:2407.21783 · full arithmetic in research/track3-flops.md

"Every parameter participates in every token." That's the sentence to say out loud. There is no lookup, no cache of answers — the whole 405B-number machine turns over for every three-quarters of a word.
make it human

810 billion operations is…

26,000years of a human doing one multiplication per second, nonstop — starting before the peak of the last Ice Age
84minutes flat-out on a Cray-1 — the fastest computer on Earth in 1976 (160 MFLOPS)
0.8milliseconds on one modern H100 GPU at peak — one H100 ≈ six million Cray-1s

And a typical chat answer is ~500 tokens: thirteen million years of human arithmetic, delivered before you finish blinking.

The per-panel beat: person → 1976 supercomputer → today. The last line is the one people repeat at lunch. (500 × 26,000 = 13M years.)
training vertigo

And that was just inference

  • Training Llama 3.1 405B: 3.8×10²⁵ FLOPs over 15.6 trillion tokens (official, Meta)
  • On the 1976 Cray-1, that training run takes 7.5 billion years — start it when Earth formed and you'd still be 3 billion years short
  • GPT-4's training is estimated at the same order: ~2×10²⁵ FLOPs (Epoch AI estimate — OpenAI has disclosed nothing)

This is why "just train your own" is not a sentence. Engines come from foundries. Everyone else builds vehicles.

The closing line is the bridge to the whole second half: you will never own the engine. Your leverage is downstream of it. If short on time, jump from here straight to The Turn.

depth · the third axis

Test-time compute is a new scaling axis

  • 2012–2022: scale the training run — more data, more parameters
  • 2022–2024: scale the post-training — RLHF, instruction tuning
  • 2024–now: scale the inference — let the same weights think longer

The same model, given 10× the thinking budget, can jump a capability tier on hard problems — capability became a dial, not a constant.

Caveat for the careful: the visible reasoning is legible, but not guaranteed to be the true cause of the answer. Treat it as a draft, not a confession.

act 05 · where this is heading

The consensus,
then the opinion

What the field broadly agrees on — kept separate, deliberately, from what I think. The flag will be visible.

Two-part act by design: consensus with citations, then MY take clearly flagged. Don't let the two blur — the audience should always know which register they're hearing.
the consensus, roughly

Four things most of the field agrees on

  1. Naive pre-training scaling has bent. The easy "10× the GPUs, get a new era" curve flattened — data, not compute, became the binding wall
  2. The gains moved axes. Post-training (RL) and test-time thinking now carry improvement — capability became a dial (Act 4)
  3. Agents are where it shows up. METR: the length of task an agent can carry at 50% success doubles every ~4–7 months — and it's accelerating, not saturating (metr.org, Time Horizon 1.1, Jan 2026)
  4. Cost per capability is collapsing. MoE, distillation, efficient inference — yesterday's frontier is next year's cheap tier (Act 3's 11×)
Careful wording: "bent," not "ended." The METR line is the most load-bearing: it's the one exponential still visibly running, and it's measured on TASKS, not benchmarks.
the trap to avoid

"Scaling is over" conflates three different curves

AxisStatus, honestly
Pre-training (bigger runs)Diminishing returns per dollar; data wall is real
Post-training (RL, distillation)Steep and young — nobody knows the ceiling
Inference (thinking longer)Scales per-task, priced per-use — a different economy entirely

Any strong claim about "the end of scaling" that doesn't say which curve is a vibe, not an argument.

the turn

AI engineering stopped

engine · harness

Nobody drives an engine down the road

The engine

  • The model — frozen weights, rented from a lab
  • Identical for you, your competitor, and a teenager in a dorm
  • You cannot tune it. You can only choose it.

The harness

  • Instructions, tools, context plumbing, permissions, memory
  • Chassis, transmission, bodywork — everything that makes an engine useful
  • 100% yours. This is the part you engineer.

The engine is a commodity. The harness is the product.

Key framing: the engine is shared infrastructure now, like the power grid. Differentiation moved one layer up. That's why this discipline got a name.
the taxonomy

There is no one correct harness

Motorcycles, cars, vans, and trucks are all correct. Shape is downstream of purpose.

VehicleThe harness it maps toBuilt for
MotorcycleBare chat + one sharp toolAn expert going fast, fully exposed

Dwell on "shape is downstream of purpose" — it kills the "which setup is best?" question before it's asked. Best for WHAT is the only version of that question that parses.
the rental car

Out of the box, Copilot is a rental car

Rental

Works anywhere, tuned for nobody. Base trim. Smells faintly of someone else. Engineered to be returnable, not to be loved.

Your car

Seat memory, mirrors set, your music. One instructions file and it knows your stack, your conventions, your definition of done.

Fleet vehicle

Spec'd for one job: racked, wrapped, upfitted. Custom agents, MCP tools, hooks in CI. Nobody asks if the fleet truck is "good in general."

People judge Copilot as a rental — they're right that it's mediocre, and wrong that it has to stay one.

Careful with tone: the insult lands on "tuned for nobody," not "badly engineered." A rental IS well-engineered — for returnability. GitHub tunes defaults for the median of 100M users, and the median user is not this room.
the law of the turn

Match the harness to the engine

  • You don't put a motorcycle frame around a truck engine.
  • You don't bolt a trailer to a superbike.
  • And when engines improve, harnesses must change shape — better engines killed the choke and the hand crank; they didn't kill the transmission.

Compensation — shrinking

Scaffolding that papers over engine weakness: few-shot walls, forced step-by-step, rigid rule lists. 2023 needed it. 2026 engines are degraded by it.

Capability — growing

Tools, context plumbing, permissions, memory. The better the engine, the more machine you can safely bolt to it.

This is the thesis slide of the whole talk. The nuance matters: harnesses aren't just "getting thinner" — the COMPENSATION layer thins while the CAPABILITY layer grows. Acts 6–7 are the evidence.

piece 1 · the seat position

One file, always applied

.github/copilot-instructions.md
# Payments service — Express + TypeScript + Prisma

## Architecture
- Routes in `src/routes/` are thin: validate, call a service, return.
- All data access goes through `src/services/` — routes never touch Prisma.
- All routes require `requireAuth` middleware unless listed in PUBLIC_ROUTES.

## Conventions
- pnpm, never npm. Strict TS — `any` fails CI.
- Errors: return typed `Result`, never throw across service boundaries.

## Definition of done
- Colocated `*.test.ts` (vitest) covering auth failure + happy path.

Applies to chat, cloud agent, and code review. Guidance: ~2 pages max, never task-specific. Saved = live, no restart. Docs: docs.github.com → “Adding repository custom instructions”.

Point at the last section: "definition of done" is the highest-leverage paragraph — it's what makes generated code arrive WITH tests. This exact file powers the next slide.

piece 2 · per-terrain suspension

Path-specific instructions

.github/instructions/db-migrations.instructions.md
---
applyTo: "prisma/migrations/**,src/services/**/*.ts"
excludeAgent: "code-review"
---
- Never edit a shipped migration; create a new one.
- Every schema change ships with a rollback note in the PR body.
- Data-shape changes require a fixture update in `test/fixtures/`.
  • Globs are comma-separated inside one string — that trips everyone
  • excludeAgent (new in 2026): keep a rule out of code review while the cloud agent still gets it
  • Overlapping files? Both are sent. Precedence is weighting, not exclusion — so write rules that don't fight
The mental model: repo-wide = who we are; path-specific = how we behave in THIS neighborhood. Migrations, generated code, legacy dirs — anywhere the general rules bend.
piece 3 · one manual, every vehicle

AGENTS.md — the cross-tool standard

  • One markdown file, read by Copilot, Claude Code, Codex, Cursor, Gemini — the emerging lingua franca
  • Lives anywhere in the repo; nearest wins — monorepo teams put one per package
  • Copilot honors CLAUDE.md and GEMINI.md as equivalents — full cross-tool convergence

vs copilot-instructions.md?

Both are injected when both exist (Copilot's file ranks higher). Pragmatic 2026 answer: write AGENTS.md as the portable manual, keep copilot-instructions.md for Copilot-only quirks — or skip it entirely.

Why it matters: your harness investment survives changing tools. Nobody wants to rewrite the manual because they switched trucks.

If asked about precedence details: documented order is personal → path-specific → repo-wide → AGENTS.md-family → org, all sent together; the nested-merge algorithm is genuinely underspecified in the docs — honest answer, sourced in research/track1-agents-md.md.

piece 5 · purpose-built vehicles

Custom agents — role, tools, model, in a file

.github/agents/planner.agent.md
---
name: Planner
description: Implementation plans for new features — no code edits
tools: ['search/codebase', 'search/usages', 'web/fetch']
model: ['Claude Opus 4.5', 'GPT-5.2']   # fallback list, in order
handoffs:
  - label: Implement Plan
    agent: agent
    prompt: Implement the plan outlined above.
---
You are in planning mode. Produce a step-by-step plan with file
paths and risks. Do NOT edit code. End with open questions.
  • Read-only by construction — tool restriction is the guardrail, not politeness
  • Agents can invoke other agents (agents: list) — sub-agent orchestration, in markdown

Formerly “custom chat modes” — same feature, renamed .agent.md, Aug 2026.

The deep point: safety by CONSTRUCTION. The planner can't edit files not because you asked nicely but because it doesn't have the tool. That principle — capability restriction over instruction — is modern harness design in one sentence.

Hooks — code that gates the agent

  "version": 1,
  "hooks": {
    "preToolUse": [{
      "type": "command",
      "matcher": "bash",
      "bash": "./scripts/guard-tool.sh",
      "timeoutSec": 10

    "postToolUse": [{
      "type": "command",

  • The guard script returns {"permissionDecision": "allow" | "deny" | "ask"} — deterministic code deciding what the model may do

act 07 · context engineering

The finite resource

What the model sees is all it is. Managing that — not writing clever prompts — is the discipline now. And it changed completely between model generations.

Two movements: (1) context as a budget, (2) the generation shift — what you did for 2023 models vs what you do now. The second is the section this deck exists for; don't rush it.
the budget

Context rot is real and measured

“Context, therefore, must be treated as a finite resource with diminishing marginal returns.” Anthropic, Effective context engineering for AI agents (2025)
  • Attention lets every token look at every other — power and cost. More context = thinner attention per fact
  • A fact on page 2 of a 300-page context isn't retrieved like a fact on page 2 of a 10-page one — models degrade on long-context retrieval long before the window "fills"
  • Corollary: a bigger window is storage, not comprehension — the fuel tank got bigger; the engine didn't
Callback to Act 3: at 128K context, attention adds ~67% on top of the 2N per-token cost. Long context is physically expensive AND cognitively diluting. That's why everything on the next slide exists.
the toolkit

Spending the budget well

TechniqueMechanismYou've already seen it
Progressive disclosureStore lightweight identifiers; load detail only when neededSkills: name+description in context, body on demand
CompactionSummarize the transcript, keep goals + recent state, continue freshNow vendor infrastructure, not app code
Structured notesAgent writes durable notes outside the window, re-reads on returnInstructions files by hand; Copilot Memory does it automatically — cited facts, 28-day expiry
Sub-agentsSpecialist burns 100K tokens exploring, returns a 1K summaryCustom agents with agents: lists

Honest cost line: agents ≈ 4× the tokens of chat; multi-agent ≈ 15× (Anthropic, multi-agent research system) — sub-agents are for when the task genuinely parallelizes, not for decoration.

The unifying idea: keep the WORKING context small and privileged; keep knowledge OUTSIDE and fetch it just in time. Memory engineering = deciding what survives the session. This is also the answer to "where's the memory act?" — it lives here.
the generation shift · 2023 → 2026

Same discipline, unrecognizable rulebook

the receipt

Anthropic deleted 80% of Claude Code's system prompt

“we removed over 80% of Claude Code's system prompt — and saw no measurable loss on our coding evaluations.” Thariq Shihipar, Anthropic — “The new rules of context engineering for Claude 5 generation models,” claude.com/blog, Jul 24 2026
  • Why it worked: the old prompt was overconstraining — stacked, sometimes contradictory rules the model had to reconcile before acting
  • “removing examples was extremely helpful, because it was just more creative than the examples we gave it”

Stated honestly: their number, their internal coding evals, frontier models only — older models still get the fat prompt, because they lack the judgment for lean instructions. Which is precisely the point: the harness was matched to the engine.

The spine's receipt. The caveat line is load-bearing — it converts the anecdote from marketing into the thesis: same product ships a THICK harness to weak engines and a THIN one to strong engines, simultaneously. That's "match the harness to the engine" running in production today.
why the old habits now hurt

2023 reflexes are 2026 bugs

“poorly-constructed prompts containing contradictory or vague instructions can be more damaging to GPT-5 than to other models, as it expends reasoning tokens searching for a way to reconcile the contradictions.” OpenAI, GPT-5 prompting guide
  • The failure mode inverted: you used to pay for too little steering (lazy, drifting models) — you now pay for too much (overtriggering, over-verification, constrained exploration)
  • And you literally pay: reconciling your contradictions burns thinking tokens you're billed for (Act 4)

Vehicle version: choke and hand-crank on a modern engine — the ritual doesn't help; now it floods the engine.

Both vendors, same finding, independently — contradictions are the new prompt bug. The billing line makes it concrete: verbose harnesses are now a line item.
what didn't change

The honesty slide

Still true, every generation

  • Clarity wins — the "new colleague test" never dies
  • Structure helps — headers, delimiters, XML tags
  • Context is finite — rot didn't go away, it moved
  • Evals gate everything — "an empirical discipline" (OpenAI)

The work didn't vanish — it moved

  • From making the model act → keeping it in scope
  • New calibration: damping over-verification, over-delegation, verbosity
  • Frontier quirks still need steering — just less of it, aimed differently
Pre-empt the "so prompting is dead?" question: no — the prompt count went down; the judgment moved up a level. You tune WHERE the model has latitude, not each behavior.

METR: measure the human-expert-time length of tasks an agent finishes half the time. That number has doubled every ~7 months since 2019, and faster since 2024 (~89–131 days). It reframes "is AI good yet?" into "how big a chore can I hand it THIS quarter?"
the theatre

What the leaderboard doesn't tell you

  • Memorization: models can name the buggy file from the issue text alone 76% of the time on SWE-bench repos — and reproduce gold patches verbatim from the task ID (SWE-Bench Illusion, arXiv:2506.12286; OpenAI audit 2026)
  • Self-grading: on one tracker, 99 of the top 100 scores are vendor-submitted with no independent run
  • Quiet exits: OpenAI's own evals team stopped reporting SWE-bench Verified in early 2026 — the benchmark's co-creators walked away from it

A saturated benchmark doesn't measure engineering anymore. It measures marketing.

Deliver dry. The Illusion result is the shocker: naming the buggy file from the issue text alone means the repo layout is memorized — the test set leaked into the engine. Sources in track3-benchmark-critiques.md.

depth · positional encoding

Position, properly

  • The original trick (2017): add a vector of sines and cosines at geometrically spaced frequencies to each token — a clock with many hands. Any position gets a unique signature; relative offsets become simple rotations, which attention can learn to read
  • Learned positions (GPT-2 era): just train a vector per slot — works, but caps the sequence length at training time
  • RoPE (the modern default): rotate query/key vectors by a position-dependent angle, so attention scores depend only on relative distance — this is what makes today's very long contexts feasible, with tricks like frequency scaling to stretch beyond training length

Good rabbit holes: “Attention Is All You Need” §3.5 · RoFormer (RoPE) paper · the positional-encoding chapter of Papyan's MAT1510 transformer deck.

depth · attention mechanics

Q·K/V, without hand-waving

  • Each token emits a query (“what am I looking for?”), a key (“what am I findable by?”), and a value (“what do I contribute if found?”) — three learned projections of the same vector
  • Score = query · key, scaled by √d, softmaxed into weights (the same softmax from Act 1); output = weighted sum of values — the token's new, context-aware vector
  • Do it with many heads in parallel per layer, stack dozens of layers, interleave with MLPs — that's the whole transformer. There is no other magic in the box
  • The n² and the caveat: naive attention compares all pairs; FlashAttention reorders the same math for memory-efficiency, and sliding/sparse/linear variants trade coverage for cost — mitigations, not repeals: context stays a budget (Act 7)

See it: Transformer Explainer's attention-matrix view (Act 2) · BertViz for head-by-head archaeology (new-tab only — Colab blocks iframes).
