Most of us know Copilot as autocomplete: grey text that suggests the next line. This talk is about agent mode, which is different. You give it a whole task, such as "fix the failing test", and it reads files, edits them and runs commands by itself until the task is done.

Copilot's agent shows up in four places. In the editor, it's agent mode in the chat panel, in VS Code or IntelliJ. In the terminal, it's the Copilot CLI. There is a desktop app for running several tasks at once. And there is a cloud agent: you assign it an issue on GitHub, it works on GitHub's machines, and you get a pull request back.

Until this year those were separate pieces of code. In October Microsoft finished merging them into one engine, called the Copilot harness, so Copilot should now behave the same in each place. Microsoft's full name for it is the Microsoft Copilot harness. That is the coding engine, not the Microsoft 365 Copilot assistant in Office. VS Code still offers the older engine, called the Local harness, as a fallback. Local is just its name; both engines run on your laptop. In this talk, engine and harness mean the same thing.

Which of these four our bank allows is our platform team's decision, and we come back to that at the end.

If asked: VS Code made the Copilot harness the default for new sessions in version 1.143, around October 21; the docs call Local a "legacy editor harness option". Copilot in JetBrains IDEs has run on the Copilot harness since August. Microsoft's reason for one engine: "Improve the harness, and every surface it touches benefits." The Copilot app became generally available on June 17; connected cloud sessions on October 28. OpenAI (one Codex core behind its CLI, IDE extension, app and SDK) and AWS (one Kiro harness behind its IDE, CLI, web and iOS apps) made the same move. VS Code can also host Anthropic's and OpenAI's own harnesses in preview; the admin setting that turns off Local blocks those too.

01 · what a harness is

Inside, Copilot runs the same simple loop as every other coding agent

ModelThe AI (OpenAI's GPT, Anthropic's Claude, Google's Gemini…) reads the conversation and picks the next step
“run the tests” →
← test output
HarnessCopilot itself: runs the step on your machine and sends back the result

The model can only write text. When it needs something done, it asks the harness, and the harness does it. This repeats until the model answers without asking for anything.

“The CLI is purely mechanical: ‘model asked for tools → execute → call model again.’ The model is the decision-maker for when to stop.” GitHub, Copilot SDK docs, “agent loop” page · read Nov 2026

GitHub Copilot SDK docs, docs/features/agent-loop.md, read 4 Nov 2026 · Claude Agent SDK docs, Nov 2026 · Ball, ampcode.com, Apr 2025

Here is how agent mode works underneath. Say you ask it to fix the failing test. The model, the AI itself, can't touch your machine. All it can do is write text, so it writes a request: run the tests. The harness, which is Copilot, runs them and sends the output back. The model reads the failure, asks to open a file, asks for an edit, and asks to run the tests again. When they pass, it writes you a normal reply with no request in it, and the loop stops.

The quote is GitHub describing Copilot. Inside the loop, the model picks each step and the harness carries it out, and the model decides when the job is done.

Every agent in this talk works this way, and the loop itself is small. In 2025 Thorsten Ball, who works on another agent called Amp, built a working one in under 400 lines of code. The products differ in what they build around it.

If asked: the request the model writes is called a tool call, and the things it can ask for (read a file, run a command) are its tools. GitHub's docs: "Each iteration of this loop is exactly one LLM API call ... There are no hidden calls." Copilot also gives the model an explicit "I'm finished" tool, task_complete. Anthropic's docs for Claude Code say the same: "Claude continues calling tools and processing results until it produces a response with no tool calls." Ball's line was "It's an LLM, a loop, and enough tokens."

Every harness in this talk has some version of these boxes.

GitHub Copilot CLI reference and changelog, Nov 2026 · VS Code Copilot docs, Nov 2026 · Liu et al., “Dive into Claude Code”, arXiv 2604.14228, v3 Oct 2026

The loop fits in a few hundred lines, so the size of these products comes from what's around it. These are Copilot's main parts. You don't need to memorise them, because each one comes back later.

Three are worth a word now. Working space: a model can only see a limited amount of text at once, measured in tokens, where a token is about a word. When a long session gets near that limit, Copilot summarises the older part so it can keep going. Safety: either you approve each action, or a second AI model approves it, and a sandbox can stop the agent's commands reaching things like the network. Extensions: MCP is a standard way to plug in outside tools, such as a ticket system, and skills and hooks are files you add to a repo to teach or check the agent.

Other harnesses have the same boxes. Researchers who read Claude Code's source code found the same picture: "Most of the code, however, lives in the systems around this loop."

If asked: the summarising is usually called compaction; the Copilot CLI does it "When your conversation approaches 95% of the token limit", and /compact does it by hand. Copilot's built-in helpers (subagents) include explore, task, code-review, research and rubber-duck. Plan mode in the CLI is enforced by the harness, though the docs call it "a safety net, not a guarantee." MCP is the Model Context Protocol. The quote is from Liu, Zhao, Shang and Shen, arXiv 2604.14228, v3, re-checked on 5 November.

Same model, different harness: small differences

GitHub, Jun 2026. Copilot against Claude Code (Anthropic's agent) and Codex (OpenAI's), on the same models: “effective parity”. This is GitHub testing itself, and Copilot was behind with the Claude models on one test.

When the harness fixes or breaks something: a big difference

Lewis, Aug 2026. A model with very little working space solved 43 of 169 bug fixes, and 72 when the harness cleared out old output. With plenty of space the change made no difference.

Anthropic, Apr 2026. Three harness changes made users think Claude had got worse. The model itself was unchanged.

GitHub blog, Basava and Castro, 25 Jun 2026 · Scale AI, arXiv 2610.24206, Oct 2026 · Lewis, arXiv 2608.26218, Aug 2026 · Anthropic, April 23 postmortem, 2026

You will hear people say Copilot is weaker than Claude Code or Codex because of its harness. The studies so far find small differences between good harnesses on the same model, and big ones only when a harness fixes a real problem or introduces one.

On the left the model stays the same. GitHub ran Copilot against Claude Code and Codex on the same models and reported "effective parity", meaning the differences were within the noise. That is GitHub marking its own homework, and its own charts show Copilot behind with the Claude models on one of the tests and ahead with the GPT models. Scale AI, an independent firm, ran three open models in three open-source harnesses. It didn't test Copilot. Which task it was mattered far more than which harness, though the harness did change the cost: one model used twice as many tokens per solved task in one harness as in another.

On the right are the exceptions. One researcher gave a model very little working space, and a harness that cleared out old output solved far more of the bug fixes. Harness changes can also break things: in April users said Claude had got worse, and Anthropic traced it to three harness changes.

If asked: GitHub used Claude Sonnet 4.6 and Opus 4.7 against Claude Code and GPT-5.4 and GPT-5.5 against Codex CLI; for benchmarks under 100 tasks it reports the best of five runs. Its chart text for SkillsBench: "Copilot CLI performed worse for Sonnet 4.6 and Opus 4.7, but better for GPT models." Scale's figures are shares of the variation in whether each attempt succeeded: task 32%, model 2.7%, harness 0.3%; the rest isn't explained by any one of the three. The model share is small because the three open models were close in ability. Per model, harness spreads were 0.9, 1.7 and 7.5 points. Kimi K3 used 1.3 million tokens per solved task in Pi against 2.6 million in mini-swe-agent. Lewis used about 20,000 tokens of space against 262,000 (with plenty of space: 102 against 101), on compressed models run locally. Anthropic's changes: a lower default effort setting, a bug that cleared the model's earlier reasoning every turn, and a prompt line asking for shorter answers; "The API was not impacted." Don't use the "45.9% versus 55.4%" Claude Code figure; it's an aggregator error.

AGENTS.md, MCP and Agent Skills are now looked after by a Linux Foundation group, so no single vendor controls them. The core of each harness, its prompts and how it manages working space, has no standard.

Linux Foundation AAIF releases, Dec 2025 and Oct 2026 · agents.md · GitHub Copilot docs, Nov 2026

The files we use to customise Copilot aren't tied to Copilot. They use open formats that other tools read too, so instruction files and skills written for Copilot would carry over if the bank ever approved another tool.

AGENTS.md is a plain Markdown file of instructions that most agents read first. MCP, the Model Context Protocol, is the standard way to connect outside tools, such as a ticket system or a database. A skill is a folder with a SKILL.md file; the agent only sees its name and description until a task needs it. Those three now belong to the Agentic AI Foundation, part of the Linux Foundation.

Hooks have no standard. Everyone copies Claude Code's format, and the Copilot CLI reads hook files from a repo's .claude folder as well as its own. A hook runs a script on your machine, so a repo you didn't write can run code when you open it with an agent. VS Code only runs workspace hooks in a trusted workspace (it asks whether you trust a folder's authors when you first open it), which is a good reason to think before you click "trust". And each vendor keeps the core of its harness to itself: the prompts and how it manages the model's working space.

If asked: AGENTS.md started at OpenAI in August 2025, MCP at Anthropic in November 2024, and Agent Skills at Anthropic in October 2025 (it joined the foundation on October 22, 2026). Copilot also reads CLAUDE.md and GEMINI.md and skills from .claude/skills. A fourth standard, ACP, lets an editor such as a JetBrains IDE drive any agent; the Copilot CLI supports it with copilot --acp, and it is how Copilot runs inside JetBrains Air. Microsoft's Agent Host Protocol (AHP, MIT) lets several apps share one live agent session. Adoption counts (60,000 projects using AGENTS.md) are the stewards' own.

How much should the harness do for the model? One side says models improve every few months, so keep the harness thin and delete whatever the next model no longer needs. The other side ships more by default.

Copilot is on the thick side. Around the model it adds Fusion, which picks a model for each prompt. It adds a rubber duck, a second model from another AI lab that critiques the plan or the code. It has Copilot Memory, which keeps notes about a repo between sessions, and admin policy controls. For a bank, thick means more is built in: some of it controls our admins can set, some of it closed code we can't inspect.

Near the thin end, the team behind Claude Code says it deletes harness code all the time. At the far thick end, Kiro from AWS has the agent write a spec before any code and checks permissions against formal rules.

GitHub's quote says the harness shapes how well the model's intelligence is used. The Scale study from section 1 found the harness explained little of the difference in results, so treat GitHub's line as its view.

04 · question 2 of 6 · finding code

Copilot can search code by meaning, which Cursor tried and then switched off

Text search (grep)

Finds every line containing an exact word or pattern, like Ctrl+F across the repo. Nothing to build or store.

Search by meaning (semantic index)

Copilot CLI, Oct 2026
“Enable semantic code search by default for online sessions.” GitHub Copilot CLI changelog, v1.0.100, 19 Oct 2026
Cursor, Jul 2026
“Semantic/embeddings indexing is being turned down in favor of grep-based retrieval” Cursor support engineer, Cursor forum

GitHub Copilot CLI changelog, 19 Oct 2026 · GitHub changelog, 17 Mar 2026 · Cursor forum, Jul 2026 · Cursor blog, Nov 2025

In a big repo, the agent first has to find the right files. Text search, usually a tool called grep, finds every line containing an exact word, like Ctrl+F across the whole repo. Search by meaning uses an index built ahead of time, so a search for "retry logic" can find code that never uses the word retry. The catch is that the index has to be built, stored and kept up to date.

Copilot does both. Its semantic index sits on GitHub's servers next to the code, and it is used by agent mode in VS Code and by the cloud agent. In October the Copilot CLI switched it on by default as well; the changelog says "for online sessions" without defining them.

Most rivals use text search only, and Cursor changed its mind. In 2025 it argued that search by meaning was necessary for large codebases. In July 2026 a Cursor support engineer wrote on its forum that the index was being turned down, and staff said it was no longer helping much.

By GitHub's own measurement, its cloud agent finished tasks 2% faster with the index, and no independent study has picked a winner yet.

If asked: the index is built from embeddings, lists of numbers that capture roughly what a chunk of code means. GitHub, March 2026: "2% less time without any change in quality." The CLI changelog doesn't define "online sessions", so don't guess. Whether the index works for code on GitHub Enterprise Server rather than github.com isn't covered by our research; ask the platform team. Cursor, November 2025: "Semantic search is currently necessary to achieve the best results, especially in large codebases" (12.5% higher accuracy on its own test); July 2026: the semantic path "was rapidly no longer helping in a meaningful way". Cursor still builds a local index to make text search fast. Claude Code, Codex and Cline keep no index; Cline wrote "We don't index your codebase, and this choice isn't an oversight." A July 2026 benchmark found "No single retrieval family dominates".

          Gemini CLI, like Copilot, ship theirs off.

      By GitHub's count, more than 40% of pull requests on GitHub in September started as an agent's draft, up from 17% in March. An independent sample of public repos found about 21%.
      
        
      GitHub changelog, Jun to Oct 2026 · GitHub Octoverse, Oct 2026 · other vendors' changelogs and blogs, Apr to Oct 2026
      
        
      
          
      Across a year of release notes, four changes keep coming up, and Copilot has shipped
          something in each, one of them still in preview.
      
          
      Agents no longer wait for someone to type. GitHub's Agentic Workflows are agent tasks
          written in a Markdown file that run as GitHub Actions jobs, so an agent can run every
          night or whenever an issue is opened. Once people run several agents at once, they need
          one screen to see them all, which is what the Copilot app is for. Dynamic workflows, which
          is a different feature despite the similar name, let a script decide which agents run and
          in what order. That one is still in preview.
      
          
      The result is more code to review. GitHub says more than 40% of pull requests on its
          platform in September started as an agent's draft; an independent tracker found about a fifth in
          public repos, so the real figure is somewhere in that range. Someone still has to read them, which
          is why so many autumn launches were review and security tools.
      
          
      Vendors expect more of the same. JetBrains' CEO expects more work to be "triggered by
          repository events, schedules, and delivery processes rather than by a developer opening
          an editor and issuing a prompt".
      
          
      If asked: Agentic Workflows run in a "sandboxed container behind the Agent
          Workflow Firewall", read-only by default, with the Copilot CLI as the default engine. Our
          research records the launch of code review Max but not how it differs, so check GitHub's
          October 28 changelog before explaining it. The 40% is GitHub counting its own platform;
          another tracker, Amplifying, found 20.8% in a sample of public pull requests, so say

          29), Devin Security (October 26). Cognition says "agents will become proactive by

          These are statements of intent.

      Keep instruction files short. A team at ETH Zurich tested agents with and without an
          AGENTS.md-style file. On average the file didn't help and added over 20% to the cost. It
          did help with unusual house rules the agent couldn't guess, so write those down and skip
          the rest.
      
          
      Steer before and check after. Instructions and skills steer the agent before it acts,
          and tests, linters and hooks catch it afterwards. In bank terms those are preventive and
          detective controls, and you want both.
      
          
      Mitchell Hashimoto, who co-founded HashiCorp, the company behind Terraform, wrote that
          when an agent makes a mistake you should change the setup so it never makes it again. In
          Copilot that means a rule, a hook or a skill.
      
          
      Fence the agent in before relying on instructions, which for us means the sandbox
          question from the last slide.
      
          
      And keep the human review real. In a sample of public repos by Amplifying, a firm that tracks agent
          activity on GitHub, more than half of merged agent pull requests had no human reviewer.
          Running Copilot code review first is my suggestion; the evidence is about the human
          step. If our branch protection already requires one, make
          sure it is an actual check and not a click.

          authors when you first open it), which
