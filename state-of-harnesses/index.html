Say hi. This is the third talk in the series. In August, Engines & Harnesses said the model is the engine and everything around it is the harness. In October, Build Your Own Harness had us writing Copilot instructions, hooks, skills and agents for a real repo.

01 · the loop

Every coding agent runs the same loop

Modelpicks the next step
tool call →
← result
Harnessruns the tool, returns the output

A tool call is the model asking the harness to act for it: read this file, run these tests. The loop ends when the model replies without one.

“It's an LLM, a loop, and enough tokens.” Thorsten Ball, Amp · “How to Build an Agent” · April 2025

Ball, ampcode.com, Apr 2025 · Claude Agent SDK docs and GitHub Copilot SDK docs, read Nov 2026

Walk the diagram with a real task. You type "fix the failing test". The model can't touch your machine, so it answers with a tool call, a structured request such as "run mvn test". The harness runs the command and sends the output back. The model reads the failure, asks to open a file, asks for an edit, and asks to run the tests again. When they pass, it writes you a plain reply with no tool call in it, and the loop stops.

The vendors describe it in nearly the same words. GitHub's Copilot SDK docs: "The CLI is purely mechanical: 'model asked for tools → execute → call model again.' The model is the decision-maker for when to stop."

Thorsten Ball, of Amp, wrote the quote in April 2025, in a post that builds a working code-editing agent in "less than 400 lines of code, most of which is boilerplate." LLM stands for large language model, the AI model itself. A token is a chunk of text, about a word or part of one, so "enough tokens" means enough room and budget for the conversation to keep going.

Backup (do not read aloud): Claude Code's Agent SDK docs say the same thing: "Claude continues calling tools and processing results until it produces a response with no tool calls." Some harnesses also give the model an explicit "I'm finished" tool. As of November 2026, Copilot has task_complete, Gemini CLI has complete_task, Cline has submit_and_exit, OpenHands has FinishTool. Ball's post is more than six months old, but the core it describes has not changed.

Liu et al., arXiv 2604.14228, v3 Oct 2026 · layers drawn from 2026 source studies and vendor docs

The loop from the last slide fits in a few hundred lines. A product like Claude Code is far bigger. Four researchers read Claude Code's publicly available source and found the loop at the centre. Around it sat seven permission modes, five layers of code for summarising old conversation, four ways to extend it, and code to run helper agents.

The eight boxes are the layers most harnesses add. Instructions means the system prompt, the standing instructions the harness sends to the model ahead of your message, plus your repo's rules, like the AGENTS.md files from October. The context window is everything the model can see at once, measured in tokens; when it fills up, the harness summarises the older part, and that is compaction. Subagents get their own fresh context and hand back a short summary. A sandbox is a fence the operating system enforces around the agent's commands. MCP, the Model Context Protocol, is the standard way to plug in outside tools.

The rest of the talk compares these boxes across vendors, and the people who build them disagree in public about how much to build.

Backup (do not read aloud): the other boxes. Code search is how the agent finds things in a big repo. Editing is the exact format the model writes changes in. Plan mode takes away the write tools so the agent can only look and propose. You built skills and hooks in October. The quote was re-checked against the paper's v3 page on 5 November 2026. The eight layers combine several source studies, so no single paper lists exactly these eight.

The first two rows are benchmarks: fixed sets of tasks with known answers, used to score models. In both, the model stays the same and only the harness changes.

First row: one author ran an open-weight model, one anyone can download and run, on their own machine with the context window set small on purpose. A harness that trimmed old tool output took it from 43 to 72 solved tasks out of 169. With a large window the same change did nothing: 102 against 101.

Second row: Scale AI ran three open-weight models in three harnesses each and worked out what explained the results. The task explained about 32%, the harness 0.3%. The harness did change cost: one model used twice as many tokens per solved task in one harness as in another.

Third row: in April, users said Claude had got worse. Anthropic traced it to three harness changes, including a lower default effort setting and a system-prompt line asking for shorter answers. The model served through the API was untouched: "The API was not impacted."

Backup (do not read aloud). Row one details: about 20,000 tokens for the small window, 262,000 for the large one. Scale tested open-weight models only, and that benchmark version is close to saturated, with scores of 87% to 99%, so there is little room for any difference to show. Each cell is a tool the harness offers the model, the thing a tool call from section 1 asks for. Read the columns left to right: read a file, search the code, change a file, run a command. Those four are the core. Web access and delegation are the common extras. Delegate means starting a subagent.

Pi has the smallest toolbox in the table. By default it has four tools: read, bash, edit and write. Its author, Mario Zechner, wrote in November 2025: "As it turns out, these four tools are all you need for an effective coding agent. Models know how to use bash and have been trained on the read, write, and edit tools with similar input schemas."

Claude Code is moving toward Pi's minimum. In April 2026 (version 2.1.117) it took Grep and Glob out of the default set on macOS and Linux, so search now runs as shell commands. Windows and npm-installed builds still have both tools, which is why the cell says "on Mac and Linux".

The room already used three of these in October. AGENTS.md is an instruction file in plain Markdown that most agents read at the start of a session. MCP is the plug for outside tools from section 1. First the two words on the line. grep is plain text search: find every line that contains this exact word or pattern, like Ctrl+F across the whole repository. A semantic index is built ahead of time from embeddings, lists of numbers that capture roughly what a chunk of code means, so a search for "retry logic" can find code that never uses the word retry. The index has to be rebuilt as the code changes, and stored somewhere.

Most harnesses sit on the left: Claude Code, Codex and Cline search with grep and keep no index.

Cursor was the loudest voice for a semantic index. In November 2025 it reported 12.5% higher accuracy on its own benchmark. In July 2026 its staff wrote that the semantic path "was rapidly no longer helping in a meaningful way" and turned it down.

Copilot went the other way. On 19 October the Copilot CLI turned semantic code search on by default. Copilot's index lives on GitHub's servers next to the code. GitHub's measured gain is small: in March its cloud agent finished tasks in "2% less time without any change in quality."

The independent evidence doesn't pick a winner.

Backup (do not read aloud): Cline wrote in 2025: "We don't index your codebase, and this choice isn't an oversight." A source-code study of eleven harnesses in July 2026 found "No system uses vector-embedding RAG for code retrieval." (RAG, retrieval-augmented generation, means looking up stored chunks and pasting them into the prompt.) Cursor trained its own embedding model for the 2025 result. Cursor still builds a local index on your machine that makes grep fast on big repositories; its docs now say it "does not store embeddings of your codebase for search." The Copilot changelog doesn't define "online sessions", so don't guess if asked. Because Copilot's index sits next to the code on GitHub, the usual worries about a stale or exposed index carry less weight. A July 2026 retrieval benchmark found "No single retrieval family dominates"; it only scored whether the agent found the right files, not task success. Junie uses the JetBrains IDE's own semantic index, and Warp keeps a semantic index too.

Both boxes make the same change to the same file, written as the model's tool call.

On the left is OpenAI's apply_patch format. Lines starting with a minus are removed, lines starting with a plus are added. There are no line numbers: the harness finds the right spot from the surrounding text and the anchor after the @@, here the method signature. Codex uses it for every model in its catalog.

On the right is find and replace, the shape of Anthropic's text editor tool: the file, the exact old text, the new text. The old text has to match exactly, and only once, or the harness returns an error and the model tries again.

Which format a model gets depends on who made it, most likely because each lab trains its models on its own format. OpenAI says that giving apply_patch its own named tool type "decreased apply_patch failure rates by 35%".

Harnesses that run many models route by model family. Copilot's open-source Local harness gives GPT-5 and later apply_patch and gives Claude replace_string_in_file. For us: Copilot picks the format from the model you choose; you never write either one.

Backup (do not read aloud): Codex defines the whole apply_patch format in a 19-line grammar. The 35% figure is from OpenAI's GPT-5.1 guide, late 2025. Claude Code's Edit tool works like the right-hand box. If someone asks whether the format makes a difference: two builders measured their own formats on weaker models, both more than six months ago. In February 2026 Can Bölük's hashline format, which tags every line so the model can point at it, took Grok Code Fast 1 from 6.7% to 68.3% on 180 React bug fixes. In December 2023 Paul Gauthier, who wrote Aider, moved GPT-4 Turbo to a simplified unified diff (the format git uses), and its score on 89 refactoring tasks went from 20% to 61%. A JetBrains study found that "search-replace format performs best for larger models across most tasks", and that "smaller open models benefit little from any formatting choice".

Some system prompts got shorter, but the whole request got longer, because the tool descriptions grew. Tool descriptions are the other big block sent with every request: a description of each tool the model may call, with its parameters.

5 · one agent or many

Multi-agent designs are back in favour, with strict rules about which agents write code

June 2025“Actions carry implicit decisions, and conflicting decisions carry bad results.” Walden Yan, Cognition (maker of Devin)
April 2026“multi-agent systems work best today when writes stay single-threaded and the additional agents contribute intelligence rather than actions” Walden Yan, Cognition (maker of Devin)
“The coordinator doesn't write code itself but directs other agents that do.” Cursor, Projects, Sep 2026

Cognition blog, Jun 2025 and Apr 2026 · Cursor blog, Projects, Sep 2026

Question five: how many agents write at once. A year ago the answer was one. In June 2025 Walden Yan at Cognition, the company behind Devin, wrote "Don't Build Multi-Agents". His argument: when two agents write code in parallel, each makes small decisions the other can't see, and the results clash.

In April 2026 he wrote a follow-up that opens "A lot has changed since then." Models got better at working as agents, and some multi-agent setups now work: a reviewer that starts with a clean context, a stronger model the agent can ask for help, a manager agent, and read-only helpers that search and report back. The rule he kept is on the slide: one agent writes, and the others contribute ideas.

Cursor's Projects feature, from September, draws the line in a different place. A coordinator hands tasks to many subagents and doesn't write code itself; the agents it directs do.

Copilot uses extra agents as readers too: the CLI's rubber duck, from the how-much-harness slide, is one of them.

Backup (do not read aloud): Yan's 2025 post recommended "a single-threaded linear agent". In 2026 he calls free-form swarms of agents negotiating with each other "mostly a distraction". Cursor Projects launched in beta on 10 September 2026; Cursor says the coordinator can direct "thousands of subagents". On 23 September Cursor also removed prompt instructions that pushed its agent to spawn subagents for exploration, citing a "coordination tax" of duplicated work. Cursor's docs say subagents share the same checkout unless they run in a git worktree (a second checkout of the repo in its own folder) or on a cloud machine. GitHub's reason for the rubber duck is that a model reviewing its own output shares "the same training data and techniques, the same blind spots" (April 2026).

None of these needs a different tool. Everything in the right-hand column exists in Copilot today; the instructions, hooks and skills are the ones we built in October.

One. A team at ETH Zurich tested agents with and without an AGENTS.md-style file. They found it "does not generally improve task success rates" and raised cost by over 20% on average. The files were useful for "specifying non-standard coding practices".

Two. Birgitta Böckeler at Thoughtworks splits a harness into guides, which steer the agent before it acts, and sensors, which check after it acts so it can correct itself. In bank terms those are preventive and detective controls.

Three. Mitchell Hashimoto, co-founder of HashiCorp, the Terraform company, wrote in February that when an agent makes a mistake, you engineer a fix so it never makes that mistake again. In practice: the second time Copilot gets something wrong, add the instruction, the hook or the skill.

Four. Anthropic's containment post says to contain at the environment layer first. In Copilot that is the local sandbox, and an admin can make it mandatory.

Five. In one public sample of merged agent pull requests, 56% had no human reviewer.

Backup (do not read aloud): ETH also found repository overviews did not help. Augment ran its own study in April and found the best files were 100 to 150 lines with a few focused reference documents, and the worst made results worse than no file; it is a vendor study on its own benchmark. Hashimoto's words, February 5: "anytime you find an agent makes a mistake, you take the time to engineer a solution such that the agent never makes that mistake again." He called the habit harness engineering. Anthropic's full line: "Design for containment at the environment layer first, then steer behavior at the model layer."
